## notify/US-000010 — Dismiss Action

### User Story

```
AS A User
I WANT to dismiss a meeting notification permanently
SO THAT I won't be reminded again for this meeting occurrence
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Behavior**: Close overlay, cancel any pending snoozes for this meeting
* **Tracking**: Mark meeting as "dismissed" in local cache (keyed by event ID + occurrence)
* **Scope**: Only dismisses this occurrence (not the series)
* **Undo**: Brief toast with "Undo" for 5 seconds after dismiss

#### Notes
1. Dismissed meetings are tracked in memory + persisted to disk
2. On app restart, dismissed meetings are loaded and skipped
3. If meeting is updated (time changed), dismiss status is cleared
4. Different from snooze - dismiss means "I don't want to be notified for this occurrence"
5. Menu bar should not show dismissed meetings

### Acceptance Criteria

```gherkin
Scenario: Dismiss closes overlay and prevents re-notification
  Given a meeting notification overlay is visible
  When the user clicks "Dismiss"
  Then the overlay closes with fade-out
  And the meeting is marked as dismissed in local cache
  And no further notifications are triggered for this meeting occurrence
  And the meeting disappears from menu bar upcoming list

Scenario: Dismiss only affects this occurrence, not the series
  Given a recurring meeting "Weekly Standup" (every Monday)
  And today's occurrence is dismissed
  When next Monday's occurrence approaches
  Then a new notification is triggered for next Monday
  And the dismiss status does not carry over

Scenario: Undo dismiss within 5 seconds
  Given the user clicks "Dismiss" on a meeting notification
  When the toast "Dismissed. Undo?" appears with 5-second countdown
  And the user clicks "Undo" within 5 seconds
  Then the meeting is removed from dismissed cache
  And the overlay reappears immediately
  And the countdown resumes from current time

Scenario: Dismiss persists across app restart
  Given a meeting is dismissed
  And the app is quit and restarted
  When the app restarts and polls calendar
  Then the dismissed meeting is not notified again
  And the dismissed status is loaded from persistent storage

Scenario: Meeting update clears dismiss status
  Given a meeting was dismissed
  And the organizer updates the meeting time (Graph API returns updated event)
  When the next poll detects the updated event
  Then the dismiss status is cleared for that event
  And a new notification is triggered for the updated time
```
