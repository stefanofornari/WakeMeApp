## notify/US-000033 — Show the Full Help on Invalid Command-Line Arguments

### User Story

```
AS A User
I WANT the complete help text when I give the command line wrong arguments
SO THAT I see what is wrong and how to fix it without looking anywhere else
```

#### Status
WIP

#### Dependencies
- notify/US-000022

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **CLI Framework**: picocli 4.x

#### Notes
1. "Invalid arguments" covers every way the command line can be rejected: unknown option, missing option value, a value of the wrong type (`--poll-interval abc`), a missing required argument (neither `--calendar` nor `--title`/`--start-date`), an unparsable date, and the other validation rules (non-positive values, window shorter than poll interval + lead time, `--calendar` pointing to a directory).
2. The output is the error message followed by the same full text printed by `--help`, written to stderr; the exit code is non-zero (2, the code picocli uses for invalid input), the same for every kind of invalid argument.
3. No exception reaches the user: no stack trace, and the application does not fail with an uncaught exception.
4. The text of `--help` and `--version` and their exit code 0 do not change.
5. Today picocli prints only its short synopsis for usage errors, and validation errors found after parsing print just "Error: ...", without any help.

### Acceptance Criteria

```gherkin
Scenario: An unknown option shows the error and the full help
  When the user runs: app --colour red
  Then the error "Unknown option: '--colour'" is printed
  And the full help text is printed after it, with all options and their descriptions
  And no stack trace is printed
  And the command exits with a non-zero code

Scenario: A missing required argument shows the full help
  When the user runs: app --title "Standup"
  Then an error says that --start-date (or --calendar) is required
  And the full help text is printed after it
  And the command exits with a non-zero code

Scenario: An invalid value shows the full help
  When the user runs: app --calendar meetings.csv --poll-interval abc
  Then an error names the option and the invalid value
  And the full help text is printed after it

Scenario: A rule violation found after parsing shows the full help
  When the user runs: app --calendar meetings.csv --poll-interval 10 --window 12
  Then the error "The window must be at least 15 minutes (poll interval 10 + lead time 5)" is printed
  And the full help text is printed after it
  And the command exits with a non-zero code

Scenario: Asking for help is not an error
  When the user runs: app --help
  Then the full help text is printed
  And the command exits with code 0
```
