## notify/US-000008 — Configurable Sound Notification

### User Story

```
AS A User
I WANT a sound to play when a meeting notification appears
SO THAT I am alerted even if I'm not looking at the screen
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Audio API**: JavaFX `MediaPlayer` / `AudioClip` for WAV/MP3
* **Bundled Sounds**: 3-4 short notification sounds (e.g., gentle chime, pop, ping)
* **Custom Sound**: User can select any WAV/MP3 file
* **Volume**: Configurable (0-100%), independent of system volume
* **Fallback**: System beep (`Toolkit.beep()`) if audio fails
* **Playback**: Non-blocking, async, plays once (not looping)

#### Notes
1. Load sounds from resources (`/sounds/`) and user-selected file
2. Pre-load default sound on app start for zero-latency playback
3. Respect "Enable notifications" setting (settings/US-000017)
4. Sound plays simultaneously with overlay appearance
5. Stop sound if user dismisses/snoozes quickly

### Acceptance Criteria

```gherkin
Scenario: Default sound plays with notification
  Given the user has not customized the notification sound
  And notifications are enabled
  When a meeting notification is triggered
  Then the default bundled sound plays once
  And the overlay appears simultaneously

Scenario: Custom sound file plays correctly
  Given the user has selected a custom WAV file in settings
  And the file exists and is readable
  When a meeting notification is triggered
  Then the custom sound plays once
  And the overlay appears simultaneously

Scenario: Sound volume is configurable
  Given the user sets notification volume to 50%
  When a notification triggers
  Then the sound plays at half the maximum amplitude
  And system volume is unaffected

Scenario: Fallback to system beep on audio failure
  Given the sound file is corrupted or missing
  When a notification triggers
  Then the system beep plays
  And the overlay still appears
  And an error is logged (not shown to user)

Scenario: Sound respects notification enable/disable
  Given notifications are disabled in settings
  When a meeting notification would trigger
  Then no sound plays
  And no overlay appears
  And the meeting is logged as "notified (disabled)"

Scenario: Multiple rapid notifications don't overlap sounds
  Given two meetings trigger within 1 second of each other
  When the notifications are processed
  Then only one sound plays (the first)
  And the second notification queues or merges
  And both meetings are shown in the overlay
```
