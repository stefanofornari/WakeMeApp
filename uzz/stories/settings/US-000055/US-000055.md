## settings/US-000055 — Keep the Calendar Value in an Owner-Only File

### User Story

```
AS A User
I WANT the calendar I configured to be remembered, in a place only I can read
SO THAT I do not have to pass it on every run, and a link that grants access to my calendar is not left in plain preferences
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (all platforms; macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Storage**: one owner-only file in the application data directory (`ProjectDirectories.from("", "", "WakeMeApp").dataLocalDir`), same write rules as `FileTokenStore` (temporary file, `rw-------`, atomic move); no encryption and no passphrase (settings/scope.md)
* **Content**: the calendar value as typed (ICS link, Graph address or CSV path); one value only
* **Precedence**: `--calendar` (one run, never saved), then the stored value, then none

#### Notes
1. Not in Preferences, never logged: shown as `https://host/…` for an ICS link wherever it is shown (calendar/US-000053).
2. This amends calendar/US-000053 note 2: the app now writes the address to this one file, and only to it (not to the settings, `dismissed.json` or the log).
3. `--print-config` gets a `calendar` line: command line or stored, ICS link as host only, `(not set)` when none (the command line part exists already).
4. If the file cannot be written the save fails with a message that does not contain the link; if it cannot be read the value is treated as not set and a warning names the file, not its content.
5. Where the platform has no POSIX permissions (Windows) the file lives in the user's own data directory and the README says it is protected by the user account only.
6. The README says: anybody who can read the user's files or a backup can read the link; how to revoke it (Outlook on the web: Publish a calendar > Unpublish).

### Acceptance Criteria

```gherkin
Scenario: A saved value is used on the next start
  Given the calendar value "https://outlook.office365.com/owa/calendar/a/b/calendar.ics" was saved
  When the application starts without arguments
  Then that calendar is polled

Scenario: The command line wins for one run and is not saved
  Given a calendar value is stored
  When the application starts with --calendar and another value
  Then the other value is polled
  And the stored value is unchanged

Scenario: The file is readable by its owner only
  When a value is saved
  Then the file permissions are rw-------

Scenario: The value never reaches Preferences or the log
  When a feed link is saved and polled
  Then the Preferences node holds no key with it
  And the log and every message show the host only

Scenario: Print-config shows the calendar masked
  Given a feed link is stored
  When the application starts with --print-config
  Then a calendar line shows "https://host/…" with "(stored)"

Scenario: An unreadable file counts as not configured
  Given the stored file cannot be read
  When the application starts
  Then a warning names the file
  And the tray icon carries the exclamation mark

Scenario: A value saved over another replaces it
  Given a value is stored
  When another value is saved
  Then only the new value is stored
```
