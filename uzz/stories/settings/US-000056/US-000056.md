## settings/US-000056 — Open the Settings Dialog

### User Story

```
AS A User
I WANT to open a settings dialog from the tray icon, or at launch
SO THAT I can change the configuration without the command line and without restarting
```

#### Status
DONE

#### Dependencies
- settings/US-000054
- settings/US-000045

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (all platforms; macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **UI technology**: styled FXML like the notification overlay: a `.fxml` view, a controller and a `.css` file under `src/main/resources/ste/wakemeapp/settings/`, no UI built in code
* **Opens**: tray item "Settings…" (enabled by this story), or `--settings` at launch (new picocli option); never by itself
* **Dialog**: JavaFX, title "WakeMeApp Settings", Save and Cancel; the content is filled by the stories that follow (settings/US-000057 first)
* **Option**: `--settings` combines with the other options; with `--print-config` the print wins and the application exits

#### Notes
1. Only one dialog at a time: opening it again brings the open one to the front.
2. Save applies without a restart; Cancel and closing the window change nothing.
3. The dialog is not modal to the notification overlay: a meeting reminder still appears while it is open.
4. Closing the dialog does not end the application (it lives in the tray, scheduler/US-000025).

### Acceptance Criteria

```gherkin
Scenario: Open from the tray
  Given the application is running in the tray
  When the user chooses "Settings…"
  Then the settings dialog is shown

Scenario: Open at launch
  When the application is started with --settings
  Then the settings dialog is shown
  And the tray icon is shown

Scenario: A second request brings the open dialog to the front
  Given the settings dialog is open
  When the user chooses "Settings…" again
  Then no second dialog appears
  And the open one comes to the front

Scenario: Cancel changes nothing
  Given the user edited a field
  When the user clicks "Cancel"
  Then the dialog closes
  And nothing is stored

Scenario: Closing the dialog keeps the application running
  When the dialog is closed
  Then the tray icon stays and polling continues

Scenario: A reminder appears while the dialog is open
  Given the dialog is open
  When a meeting reaches its lead time
  Then the overlay is shown above everything
```
