## settings/US-000058 — Show an About Dialog from the Tray Menu

### User Story

```
AS A User
I WANT an "About WakeMeApp" item in the tray menu that shows an About dialog
SO THAT I can tell which version of the application is running and where to find help
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (all platforms; macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Menu**: the item "About WakeMeApp" is added to the tray menu of settings/US-000054, above "Quit"; the menu otherwise stays as it is
* **Content**: application name, version, a one-line description, the project link (https://github.com/stefanofornari/WakeMeApp) and the licence (Apache License 2.0)

#### Notes
1. The version comes from the build (the Maven project version, available to the running application as a bundled resource), never typed twice; if it cannot be read the dialog shows "unknown" instead of failing.
2. Only one About dialog at a time: choosing the item again brings the open one to the front.
3. A JavaFX dialog with a single Close button; closing it does not end the application (it lives in the tray, scheduler/US-000025) and it does not block a meeting reminder (the overlay still appears while it is open).
4. The project link is selectable text (or opens in the browser); nothing else is sent anywhere.
5. Independent of the settings dialog (settings/US-000056): it needs neither the stored settings nor a configured calendar.

### Acceptance Criteria

```gherkin
Scenario: The menu has an About item
  Given the application is running in the tray
  When the user opens the tray menu
  Then the menu contains "About WakeMeApp", "Settings…" and "Quit"

Scenario: Open the About dialog
  Given the application is running in the tray
  When the user chooses "About WakeMeApp"
  Then a dialog is shown with the application name, the version, the project link and the licence
  And the version is the one of the running build

Scenario: Only one dialog at a time
  Given the About dialog is open
  When the user chooses "About WakeMeApp" again
  Then no second dialog is opened
  And the open one is brought to the front

Scenario: Closing the dialog keeps the application running
  Given the About dialog is open
  When the user closes it
  Then the application keeps running in the tray

Scenario: A reminder is not blocked by the dialog
  Given the About dialog is open
  When a meeting notification is due
  Then the notification overlay is shown

Scenario: The version cannot be read
  Given the build information is not available
  When the user chooses "About WakeMeApp"
  Then the dialog is shown with the version "unknown"
```
