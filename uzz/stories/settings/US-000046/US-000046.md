## settings/US-000046 — Overrule Settings from the Command Line

### User Story

```
AS A User
I WANT to give a setting on the command line for one run
SO THAT I can try a value, or run without the settings UI, without changing what is stored
```

#### Status
DONE

#### Dependencies
- settings/US-000045

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25; `java.prefs` only, no new dependency; tests use an injected Preferences node, never the real user root; command line with picocli (`NotificationCommand`, already in the project)
* **New options**: `--client-id <uuid>`, `--tenant <id>`
* **Existing options**: `--poll-interval`, `--window` (and the others) keep their meaning; moving their defaults to the stored settings is done together with the story that stores them

#### Notes
1. Precedence for every setting: command line, then stored, then built-in default.
2. A command line value is never written to the store.
3. Validation is the same whatever the source: client ID is a UUID, tenant is a UUID or `organizations` (see settings/US-000014); an invalid command line value stops the start with a message naming the option.
4. A stored value that is not valid is ignored with a WARNING naming the key (the application does not stop for something saved earlier); the default applies.
5. Until the settings UI exists there is no way to store the client ID and tenant: they are passed on every run.

### Acceptance Criteria

```gherkin
Scenario: The command line overrules the stored value
  Given the stored tenant is "organizations"
  When the application starts with --tenant 11111111-2222-3333-4444-555555555555
  Then that tenant is used
  And the stored tenant is still "organizations"

Scenario: The stored value is used without an option
  Given the stored client ID is a valid UUID
  When the application starts without --client-id
  Then the stored client ID is used

Scenario: The default is used when nothing is given or stored
  Given no tenant is stored
  When the application starts without --tenant
  Then the tenant is "organizations"

Scenario: An invalid option stops the start
  When the application starts with --client-id not-a-uuid
  Then it does not start
  And the message says that --client-id must be a UUID
```
