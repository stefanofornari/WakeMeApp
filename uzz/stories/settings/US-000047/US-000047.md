## settings/US-000047 — Print the Effective Configuration

### User Story

```
AS A User or a Support Person
I WANT to see every setting the application would use and where each comes from
SO THAT I can check a configuration on any operating system without native tools
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25; `java.prefs` only, no new dependency; tests use an injected Preferences node, never the real user root; command line with picocli
* **Option**: `--print-config`

#### Notes
1. Prints one line per setting on stdout: key, effective value, source (`command line`, `stored` or `default`); then exits with status 0 without starting the application.
2. Same output on every platform; it is the documented first way to inspect (settings/US-000044).
3. Nothing in the output is a secret; the token cache is never printed.
4. Keys that are stored but unknown to the application are listed as `stored (unknown key)`.

### Acceptance Criteria

```gherkin
Scenario: Each setting shows its source
  Given a stored lead time of 10 and no stored poll interval
  When the application runs with --print-config --poll-interval 2
  Then the output shows the lead time as 10 from "stored"
  And the poll interval as 2 from "command line"
  And the tenant as "common" from "default"

Scenario: Printing does not start the application
  When the application runs with --print-config
  Then it exits with status 0
  And no calendar is read and no window is shown

Scenario: Unknown stored keys are shown
  Given a stored key the application does not know
  When the application runs with --print-config
  Then the key is listed as "stored (unknown key)"

Scenario: The tokens are not printed
  Given a saved sign-in
  When the application runs with --print-config
  Then no token appears in the output
```
