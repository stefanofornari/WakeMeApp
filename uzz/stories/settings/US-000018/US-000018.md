## settings/US-000018 — Test Notification Button

### User Story

```
AS A User
I WANT a "Test Notification" button in settings
SO THAT I can verify my notification setup (sound, overlay, join button) works correctly
```

#### Status
DONE

#### Dependencies
- notify/US-000005
- notify/US-000006
- notify/US-000007
- notify/US-000008

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **UI technology**: styled FXML like the notification overlay: a `.fxml` view, a controller and a `.css` file under `src/main/resources/ste/wakemeapp/settings/`, no UI built in code
* **UI**: Button in settings dialog labeled "Test Notification"
* **Behavior**: Triggers a fake meeting notification with all configured options
* **Test Meeting**: Title "Test Meeting", starts in 5 minutes, dummy Teams URL
* **Scope**: Bypasses scheduler, directly calls notification engine
* **Works Regardless**: Functions even when notifications are globally disabled

#### Notes
1. Uses same code path as real notifications (full integration test)
2. Includes sound, overlay, countdown, join button, snooze, dismiss
3. Join button opens a harmless test URL (e.g., https://example.com)
4. Auto-dismisses after 10 seconds if no interaction
5. Useful for troubleshooting sound, display, permission issues

### Acceptance Criteria

```gherkin
Scenario: Test notification triggers full notification stack
  Given the user is on the settings dialog
  When the user clicks "Test Notification"
  Then a full-screen overlay appears (notify/US-000005)
  And the configured sound plays (notify/US-000008)
  And the countdown shows "05:00" and counts down (notify/US-000006)
  And "Join Meeting" button is visible (notify/US-000007)
  And "Snooze" and "Dismiss" buttons work

Scenario: Test notification works when globally disabled
  Given notifications are disabled (settings/US-000017)
  When the user clicks "Test Notification"
  Then the test notification appears normally
  And the global disable setting remains off

Scenario: Test join button opens test URL
  Given a test notification is visible
  When the user clicks "Join Meeting"
  Then the browser opens https://example.com (or configured test URL)
  And the overlay closes

Scenario: Test notification auto-dismisses
  Given a test notification is visible
  And the user does not interact for 10 seconds
  Then the overlay fades out and closes
  And no error is logged

Scenario: Test notification respects sound selection
  Given the user selected "Custom Sound" in settings/US-000016
  When the user clicks "Test Notification"
  Then the custom sound plays (not the default)
  And volume matches the configured setting
```
