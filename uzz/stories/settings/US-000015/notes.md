# Notes — settings/US-000015

* Logic in `LeadTime` (key `notify.leadTimeMinutes`, choices 1, 2, 5, 10, 15, default 5), tested without JavaFX. A stored value that is not a choice is ignored with a warning, like the Microsoft settings. `--print-config` lists it (`ConfigReport`; the key column is now 22 wide so `notify.leadTimeMinutes` lines up).
* Revised after the first version: the free number field and its messages (1 to 1440) were replaced by a select box with the five choices. A choice shorter than the poll interval is prevented in the UI instead of warned about after the save: the list cells for those are disabled, and the select box has a tooltip (visible, not intrusive) with the reason and the remedy. `LeadTime.allowed(pollInterval)` and `LeadTime.tooltip(pollInterval)` hold the rule. If the saved value is itself shorter than the poll interval (the interval was raised later) it is still shown and Save leaves it alone; picking another disallowed one from code is refused. With a poll interval longer than every choice nothing can be picked.
* Apply at once (decision of the scope review): `SettingsListener.leadTimeSaved` makes `CLILauncher` stop the poller and scheduler and poll the same calendar again (`repoll`), so what is scheduled is scheduled again with the new lead time and an already passed trigger fires at once. If the calendar was changed in the same Save only `calendarSaved` is called: it polls the new calendar with the new lead time anyway.
* The lead time of the scheduler comes from the stored setting only (no command-line option). The poll window is now `max(--window, poll interval + lead time)` (`CalendarPoller.effectiveWindow`), so a long lead time still sees its meetings; the check of an explicit `--window` at startup still uses the default 5 minutes.
* The poll interval is a command-line option only, so the dialog compares with the one of this run.
* Dependency changed from the canceled scheduler/US-000011 to scheduler/US-000023 (scheduler core and lead time).
* Not verified here: `SettingsDialogTest` and the launcher (JavaFX, TestFX, picocli) need `mvn test`; `LeadTimeTest`, `ConfigReportTest` and `CalendarPollerTest` were run.
