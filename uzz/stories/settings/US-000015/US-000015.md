## settings/US-000015 — Default Lead Time Setting

### User Story

```
AS A User
I WANT to configure how many minutes before a meeting I'm notified
SO THAT I have enough time to prepare without being interrupted too early
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **UI technology**: styled FXML like the notification overlay: a `.fxml` view, a controller and a `.css` file under `src/main/resources/ste/wakemeapp/settings/`, no UI built in code
* **Input**: Spinner/Number field (1-1440 minutes, default: 5)
* **Storage**: Java Preferences, see settings/scope.md (plain text, non-sensitive)
* **Runtime Effect**: Scheduler (scheduler/US-000011) uses this for notification timing
* **Immediate Effect**: Changes apply to next poll cycle (not retroactive)

#### Notes
1. Lead time = minutes before meeting start to trigger notification
2. Minimum 1 minute, maximum 1440 (24 hours)
3. Poll interval should be ≤ lead time (enforced in validation)
4. Snooze "Until meeting starts" uses this implicitly (meetingStart - leadTime)

### Acceptance Criteria

```gherkin
Scenario: Lead time setting saves and affects notifications
  Given the user sets lead time to 10 minutes
  And a meeting is scheduled for 10:00 AM
  When the scheduler runs
  Then the notification triggers at 9:50 AM (10 minutes before)

Scenario: Lead time validation enforces minimum
  Given the user enters 0 or negative number
  When the user tries to save
  Then an error appears: "Lead time must be at least 1 minute"
  And the value is reset to 1

Scenario: Lead time validation enforces maximum
  Given the user enters 2000
  When the user tries to save
  Then an error appears: "Lead time cannot exceed 1440 minutes (24 hours)"
  And the value is reset to 1440

Scenario: Poll interval warning when greater than lead time
  Given poll interval is 10 minutes
  And lead time is set to 5 minutes
  When the user saves
  Then a warning appears: "Poll interval (10 min) exceeds lead time (5 min). Notifications may be delayed."
  And settings are still saved

Scenario: Change takes effect on next poll
  Given lead time is 5 minutes
  And a meeting at 10:00 AM (notification scheduled for 9:55 AM)
  When the user changes lead time to 15 minutes at 9:52 AM
  And the next poll runs at 9:55 AM
  Then the notification for 10:00 AM is rescheduled to 9:45 AM (already passed)
  And the notification triggers immediately (or at next scheduler tick)
```
