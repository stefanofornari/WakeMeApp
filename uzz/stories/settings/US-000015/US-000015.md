## settings/US-000015 — Default Lead Time Setting

### User Story

```
AS A User
I WANT to configure how many minutes before a meeting I'm notified
SO THAT I have enough time to prepare without being interrupted too early
```

#### Status
DONE

#### Dependencies
- settings/US-000045
- settings/US-000056
- scheduler/US-000023

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **UI technology**: styled FXML like the notification overlay: a `.fxml` view, a controller and a `.css` file under `src/main/resources/ste/wakemeapp/settings/`, no UI built in code
* **Input**: select box with the choices 1, 2, 5, 10 and 15 minutes (default: 5); no free text
* **Storage**: Java Preferences, see settings/scope.md (plain text, non-sensitive)
* **Runtime Effect**: Scheduler (scheduler/US-000011) uses this for notification timing
* **Immediate Effect**: Changes apply to next poll cycle (not retroactive)

#### Notes
1. Lead time = minutes before meeting start to trigger notification
2. Only the five choices exist; a stored value that is none of them is ignored (default 5, with a warning in the log)
3. A choice shorter than the poll interval cannot be picked (greyed out); a tooltip on the select box says why and how to allow it (a shorter `--poll-interval`). The poll interval is a command-line option only
4. Snooze "Until meeting starts" uses this implicitly (meetingStart - leadTime)

### Acceptance Criteria

```gherkin
Scenario: Lead time setting saves and affects notifications
  Given the user chooses 10 minutes
  And a meeting is scheduled for 10:00 AM
  When the scheduler runs
  Then the notification triggers at 9:50 AM (10 minutes before)

Scenario: Only the choices are offered
  When the settings dialog is open
  Then the select box offers 1, 2, 5, 10 and 15 minutes
  And 5 minutes is selected if nothing else was saved

Scenario: Choices shorter than the poll interval cannot be picked
  Given the poll interval is 10 minutes
  When the user opens the select box
  Then 1, 2 and 5 minutes are greyed out and cannot be selected
  And a tooltip says that the poll interval is 10 min and a shorter lead time could make a reminder late

Scenario: Nothing to explain when every choice is allowed
  Given the poll interval is 1 minute
  Then no choice is greyed out
  And there is no tooltip

Scenario: A stored value that is not a choice is ignored
  Given the stored lead time is 12
  When the application starts
  Then 5 minutes is used
  And a warning is logged

Scenario: Change takes effect at once
  Given lead time is 5 minutes
  And a meeting at 10:00 AM (notification scheduled for 9:55 AM)
  When the user changes lead time to 15 minutes at 9:52 AM and saves
  Then the calendar is polled again at once
  And the notification for 10:00 AM is rescheduled to 9:45 AM (already passed)
  And it triggers immediately
```
