## settings/US-000014 — Microsoft Graph Configuration

### User Story

```
AS A User
I WANT to configure Microsoft Graph connection settings (Tenant ID, Client ID)
SO THAT the app can connect to my organization's Outlook/Teams calendar
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Fields**: Tenant ID (optional, defaults to "common"), Client ID (required)
* **Validation**: Client ID format (UUID), Tenant ID format (UUID or "common"/"organizations")
* **Storage**: Java Preferences, node `/ste/wakemeapp` (see settings/scope.md); the same values `--client-id` and `--tenant` save
* **UI**: Settings tab with form fields, "Save" button, validation feedback
* **Default**: Tenant ID = "common" (multi-tenant), works for most users

#### Notes
1. Client ID must be registered in Azure AD by user/admin
2. Redirect URI not needed for Device Code Flow
3. Required API permissions: `Calendars.Read`, `User.Read`
4. On save: validate by attempting token request (test connection)
5. Clear stored tokens when Client ID/Tenant ID changes
6. Help text with link to Azure AD app registration guide

### Acceptance Criteria

```gherkin
Scenario: Valid configuration saves and enables authentication
  Given the user enters a valid Client ID (UUID format)
  And Tenant ID is "common" or valid UUID
  When the user clicks "Save"
  Then the settings are stored in the Preferences
  And any existing tokens are cleared (re-auth required)
  And a "Test Connection" button becomes enabled
  And the status shows "Configuration saved"

Scenario: Invalid Client ID shows validation error
  Given the user enters "not-a-uuid" as Client ID
  When the user clicks "Save"
  Then an error appears: "Client ID must be a valid UUID"
  And settings are not saved
  And the field is highlighted in red

Scenario: Test connection validates Azure AD registration
  Given valid Client ID and Tenant ID are saved
  When the user clicks "Test Connection"
  Then a Device Code Flow is initiated (auth/US-000001)
  And if authentication succeeds, a success message appears
  And if the app registration is missing permissions, an error explains required scopes
  And if Client ID is invalid, an error: "Invalid client - check Azure AD registration"

Scenario: Changing Client ID clears stored tokens
  Given the user has authenticated and tokens are stored
  When the user changes the Client ID and saves
  Then all stored tokens are deleted
  And the next poll triggers re-authentication (auth/US-000001)
  And the user is prompted to authenticate with new credentials

Scenario: Default Tenant ID works for most users
  Given the user leaves Tenant ID empty
  When the user saves settings
  Then "common" is used as default Tenant ID
  And authentication works for personal and work/school accounts
```
