## settings/US-000060 — Last Update in the Tray Menu

### User Story

```
AS A User
I WANT the tray menu to show when the calendar was last read
SO THAT I can tell at a glance that WakeMeApp is up to date, or that it has stopped reading my calendar
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app, tray menu of dorkbox SystemTray
* **Menu**: Settings…, About WakeMeApp, Quit, then a separator and a disabled (read-only) item "Last update: …"; clicking it does nothing
* **Meaning**: the time of the last *successful* read of the calendar, whatever its kind (ICS link, Graph, CSV file); a failed poll leaves it unchanged
* **Format**: "Last update: 16:49" (short time of the system locale) when it was today, "Last update: 18 Nov, 16:49" (date and time) when it was another day, "Last update: —" when nothing is stored
* **Storage**: Java Preferences, key `calendar.last_update`, a UTC ISO-8601 instant; it is state, not a setting: the dialog does not show it. The key is added to the known keys of `--print-config` and to docs/settings.md
* **Always shown**: also when nothing is polled (tray only without a calendar, a single meeting from the command line), where it shows the stored time or "—"

#### Notes
1. After a successful poll the key is written and the item refreshed, including the poll that follows saving the calendar, the lead time or the poll interval in the dialog.
2. Saving a different calendar in the dialog clears the key: the stored time belonged to the old calendar. The item shows "—" until the new calendar has been read.
3. After a restart the item shows the stored time, which may be hours old, until the first poll replaces it; a failed first poll leaves it, which is the intended signal.
4. A `--calendar` run that is not saved also writes the key when it reads successfully (accepted: the time may then refer to another calendar than the saved one).
5. The poller needs a "poll succeeded" callback (none exists today), and the tray menu, built once so far, must change its item at runtime (`TrayView.setLastUpdate(String)`; formatting with an injected clock and locale so a test can fix them).
6. A "Refresh now" item, the last error, relative text ("5 min ago") and the tooltip are out of scope.

### Acceptance Criteria

```gherkin
Scenario: The item after Quit
  When the user opens the tray menu
  Then after "Quit" there is a separator and a disabled item "Last update: …"

Scenario: A successful read
  Given the calendar was read successfully at 16:49 today
  Then the item shows "Last update: 16:49"
  And the key calendar.last_update holds that instant

Scenario: An earlier day
  Given the last successful read was on 18 November at 16:49 and today is 19 November
  Then the item shows the date and the time

Scenario: A failed poll
  Given the last successful read was at 16:49
  When the next poll fails
  Then the item still shows 16:49

Scenario: Nothing read yet
  Given the key is not set
  Then the item shows "Last update: —"

Scenario: After a restart
  Given the key holds the time of a read made before the application was stopped
  When the application starts
  Then the item shows that time until the first poll of this run succeeds

Scenario: Another calendar
  Given a last update is stored
  When the user saves a different calendar in the settings dialog
  Then the key is cleared and the item shows "Last update: —"
  And a successful read of the new calendar sets it again

Scenario: Read-only
  When the user clicks the item
  Then nothing happens

Scenario: Known key
  When --print-config runs with the key stored
  Then it is not reported as an unknown key
```
