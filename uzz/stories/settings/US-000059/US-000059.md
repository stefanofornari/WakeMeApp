## settings/US-000059 — Poll Interval Setting

### User Story

```
AS A User
I WANT to choose in the settings dialog how often the calendar is checked
SO THAT I can balance how quickly a new or moved meeting is noticed against how often the calendar is read
```

#### Status
DONE

#### Dependencies
- settings/US-000045
- settings/US-000056
- calendar/US-000031

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **UI technology**: styled FXML, in the Notifications section of the dialog (settings/US-000056)
* **Input**: select box with the choices 1, 2, 5, 10, 15 and 30 minutes (default: 5); no free text
* **Storage**: Java Preferences, key `poll.intervalMinutes`
* **Precedence**: `--poll-interval` (this run only) > stored value > 5. Saving a poll interval in the dialog replaces the option for the rest of the run.

#### Notes
1. It applies at once: the calendar being polled is polled again with the new interval.
2. It does not limit the lead time: a lead time shorter than the poll interval is fine, because the meetings are read ahead of time (the window grows to poll interval + lead time, see calendar/US-000031).
3. A stored value that is none of the choices is ignored (default 5, with a warning in the log).

### Acceptance Criteria

```gherkin
Scenario: Choose the poll interval
  Given the settings dialog is open
  When the user chooses "15 minutes" and saves
  Then the value is stored
  And the calendar is polled every 15 minutes from now on, without a restart

Scenario: Default
  Given nothing is stored
  When the settings dialog opens
  Then the poll interval shows "5 minutes"

Scenario: The command line wins for one run
  Given 15 minutes is stored
  When the application starts with --poll-interval 2
  Then the calendar is polled every 2 minutes
  And the stored value is not changed

Scenario: Poll interval and lead time are independent
  Given the poll interval is 15 minutes
  When the user chooses a lead time of 1 minute
  Then it is accepted
```
