## settings/US-000045 — Store Settings in Java Preferences

### User Story

```
AS A User
I WANT the application to keep my settings between runs
SO THAT I do not have to give them again each time it starts
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25; `java.prefs` only, no new dependency; tests use an injected Preferences node, never the real user root
* **Node**: user root, `/ste/wakemeapp`
* **Scope**: the storage only (typed read/write with default); the settings that use it are in their own stories (settings/US-000014 to US-000017)

#### Notes
1. One small class (`Settings`) takes the Preferences node in its constructor; production passes the real node, tests pass a temporary one.
2. Typed getters with a default (string, int, boolean) and setters; every write is followed by `flush()`.
3. A value of the wrong type (an int key holding text) gives the default and a WARNING naming the key; it never throws.
4. If the store cannot be read or written (`BackingStoreException`), a read gives the default and a write fails with a WARNING; the application keeps running.
5. Keys are namespaced by meaning, e.g. `graph.clientId`, `graph.tenant`, `notify.leadMinutes`; the list is kept in docs/settings.md (settings/US-000044).

### Acceptance Criteria

```gherkin
Scenario: A stored value is read back
  Given the setting "notify.leadMinutes" was set to 10
  When a new Settings is created on the same node
  Then the value 10 is returned

Scenario: A missing value gives the default
  Given nothing is stored for "notify.leadMinutes"
  When it is read with default 5
  Then 5 is returned

Scenario: A value of the wrong type gives the default
  Given the stored text "abc" for an int setting
  When it is read with default 5
  Then 5 is returned
  And a WARNING names the key

Scenario: A write is flushed
  Given a Settings on a node
  When a value is set
  Then the node has been flushed

Scenario: A broken store does not stop the application
  Given a node whose store cannot be read
  When a value is read
  Then the default is returned
  And a WARNING says the settings could not be read
```
