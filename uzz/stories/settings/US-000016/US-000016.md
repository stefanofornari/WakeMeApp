## settings/US-000016 — Sound Selection

### User Story

```
AS A User
I WANT to choose which sound plays for meeting notifications
SO THAT I can pick a sound that gets my attention without being jarring
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **UI technology**: styled FXML like the notification overlay: a `.fxml` view, a controller and a `.css` file under `src/main/resources/ste/wakemeapp/settings/`, no UI built in code
* **Bundled Sounds**: 4 options (Chime, Pop, Ping, Gentle Bell) - short WAV files
* **Custom Sound**: File picker for WAV/MP3/OGG
* **Preview**: Play button next to each option
* **Volume**: Slider (0-100%, default 80%)
* **Storage**: Java Preferences, see settings/scope.md (sound name or custom file path)

#### Notes
1. Bundled sounds in `/resources/sounds/` (included in JAR)
2. Custom file path stored relative if in config dir, absolute otherwise
3. Validate custom file exists and is playable on save
4. Preview uses same playback code as notifications (notify/US-000008)
5. "None" option = silent notifications (visual only)

### Acceptance Criteria

```gherkin
Scenario: Select bundled sound and preview
  Given the settings dialog is open
  When the user selects "Gentle Bell" from the dropdown
  And clicks "Preview"
  Then the "Gentle Bell" sound plays once at configured volume
  And the selection is highlighted

Scenario: Select custom sound file
  Given the user selects "Custom File..." from dropdown
  When the file picker opens
  And the user selects a valid WAV file
  Then the file path is stored
  And "Preview" plays the custom file
  And the dropdown shows the filename

Scenario: Custom sound validation
  Given the user selects a non-audio file (e.g., .txt)
  When the user tries to save
  Then an error appears: "Selected file is not a valid audio format"
  And the custom selection is cleared

Scenario: Volume slider affects preview and notifications
  Given the user sets volume to 30%
  When the user clicks "Preview" for any sound
  Then the preview plays at 30% volume
  And subsequent notifications play at 30% volume

Scenario: "None" option disables sound
  Given the user selects "None (Silent)"
  When a notification triggers
  Then no sound plays (notify/US-000008)
  And the overlay still appears
  And the sound dropdown shows "None (Silent)" as selected

Scenario: Missing custom file falls back to default
  Given the user previously selected a custom file
  And the file has been moved/deleted
  When a notification triggers
  Then the default bundled sound plays
  And a warning is logged
  And the settings UI shows a warning icon next to the sound selector
```
