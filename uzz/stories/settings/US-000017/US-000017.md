## settings/US-000017 — Enable/Disable Notifications

### User Story

```
AS A User
I WANT to globally enable or disable meeting notifications
SO THAT I can temporarily silence notifications during focused work or meetings
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **UI**: Toggle switch in Settings, also in menu bar (scheduler/US-000012)
* **Storage**: Java Preferences, see settings/scope.md (boolean)
* **Immediate Effect**: No restart required
* **Visual Indicator**: Menu bar icon changes (e.g., grayed out, slash overlay)

#### Notes
1. When disabled: scheduler still polls but suppresses notification triggers
2. Dismissed/snoozed meetings respect disable state (no re-notification)
3. "Test Notification" button (settings/US-000018) works regardless of this setting
4. Keyboard shortcut for quick toggle (future enhancement)
5. Focus mode integration (macOS) - optional future

### Acceptance Criteria

```gherkin
Scenario: Disable notifications suppresses all meeting alerts
  Given notifications are enabled
  And a meeting is in 5 minutes
  When the user disables notifications in settings
  Then the meeting notification does not appear at the lead time
  And the scheduler logs "Notification suppressed (globally disabled)"
  And the menu bar icon shows disabled state

Scenario: Enable notifications restores alerting
  Given notifications are disabled
  And a meeting is in 10 minutes
  When the user enables notifications
  And the next scheduler poll runs
  Then the meeting notification is scheduled and triggers at lead time
  And the menu bar icon shows enabled state

Scenario: Menu bar toggle matches settings
  Given notifications are enabled
  When the user clicks "Pause Notifications" in menu bar
  Then notifications are disabled
  And the Settings UI shows the toggle as disabled
  And vice versa

Scenario: Test notification works when disabled
  Given notifications are disabled
  When the user clicks "Test Notification" in settings
  Then a test notification appears (full-screen overlay + sound)
  And the global disable setting is unaffected

Scenario: State persists across restart
  Given notifications are disabled
  When the app is quit and restarted
  Then notifications remain disabled
  And the UI reflects the disabled state
```
