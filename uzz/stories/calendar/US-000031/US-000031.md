## calendar/US-000031 — Configure Poll Interval and Window from the Command Line

### User Story

```
AS A User
I WANT to set the poll interval and the window when I start the app
SO THAT I can tune how often the calendar is checked and how far ahead it looks
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Defaults**: poll interval 5 min, window 15 min; settings UI (settings/US-000015) is out of scope

#### Notes
1. Proposed options: `--poll-interval <minutes>` and `--window <minutes>`, added to the picocli command of notify/US-000022.
2. Constraint: window >= poll interval + lead time (lead time 5 min until settings/US-000015). A violation is rejected with an error, not corrected or warned about.
3. Values must be positive whole minutes.

### Acceptance Criteria

```gherkin
Scenario: Defaults apply when the options are omitted
  When the user starts the app without --poll-interval and --window
  Then the poller uses 5 minutes and 15 minutes

Scenario: Valid values are used
  When the user starts the app with --poll-interval 2 --window 12
  Then the poller runs every 2 minutes and asks for a 12 minute window

Scenario: A window shorter than poll interval plus lead time is rejected
  Given the lead time is 5 minutes
  When the user starts the app with --poll-interval 10 --window 12
  Then an error explains that the window must be at least 15 minutes
  And nothing is polled or scheduled
  And the command exits with a non-zero code

Scenario: Non-positive values are rejected
  When the user starts the app with --poll-interval 0
  Then an error is printed and the command exits with a non-zero code
```
