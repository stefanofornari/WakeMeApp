## calendar/US-000004 — Extract Meeting Details for Notifications

### User Story

```
AS A User
I WANT the following meeting details extracted from my calendar: title, start/end time, join link, organizer
SO THAT my notifications show the right information and the "Join" button works
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Input**: Raw JSON from `/me/calendar/events`
* **Output**: Normalized `Meeting` domain object
* **Required Fields**: id, title, start/end (ZonedDateTime), joinUrl, organizer (name + email), description, isOnlineMeeting, meetingType (Teams, Skype, etc.)

#### Notes
1. Extract Teams join URL from `onlineMeeting.joinUrl` or `onlineMeetingUrl`
2. Handle missing/optional fields gracefully (description may be null)
3. Parse organizer from `organizer.emailAddress`
4. Detect meeting type from `onlineMeetingProvider` (teamsForBusiness, skypeForBusiness, unknown)
5. Filter out non-meeting events (appointments without join URL) unless configured otherwise
6. Handle recurring events (seriesMasterId, recurrence pattern)

### Acceptance Criteria

```gherkin
Scenario: User sees correct meeting info in notification
  Given a Graph event response with all fields populated for a Teams meeting
  When the parser processes the event
  Then a Meeting object is created with:
    | Field          | Value                              |
    | id             | Graph event id                     |
    | title          | event.subject                      |
    | startTime      | parsed start.dateTime in user TZ   |
    | endTime        | parsed end.dateTime in user TZ     |
    | joinUrl        | onlineMeeting.joinUrl              |
    | organizerName  | organizer.emailAddress.name        |
    | organizerEmail | organizer.emailAddress.address     |
    | description    | body.content (HTML stripped)       |
    | isOnlineMeeting| true                               |
    | meetingType    | TEAMS                              |
  And the notification displays the title, time, and organizer correctly
  And the "Join Meeting" button opens the correct Teams URL

Scenario: User gets correct info even when some fields are missing
  Given a Graph event response with no description and no onlineMeeting.joinUrl
  When the parser processes the event
  Then a Meeting object is created with:
    | Field          | Value                              |
    | description    | "" (empty string)                  |
    | joinUrl        | onlineMeetingUrl (fallback)        |
    | meetingType    | TEAMS (if provider is teamsForBusiness) |
  And the notification still works with available information

Scenario: Recurring meetings are handled correctly
  Given a recurring meeting series (e.g., weekly standup)
  When the parser processes the series master and occurrences
  Then the Meeting object includes recurrence info
  And individual occurrences are calculated for the polling window
  And the user receives a notification for each occurrence at the right time

Scenario: Non-meeting appointments don't clutter notifications
  Given a Graph event with isOnlineMeeting=false and no join URL (regular appointment)
  When the parser processes the event
  Then the event is marked as non-joinable
  And the notification engine can filter based on configuration
  And the user doesn't get a "Join" button for events they can't join

Scenario: All-day events show correct timing
  Given a Graph event with isAllDay=true
  When the parser processes the event
  Then startTime is set to midnight in user's timezone
  And endTime is set to midnight of following day
  And lead time calculation uses the all-day start
  And the user receives notification at the configured lead time before the all-day event
```
