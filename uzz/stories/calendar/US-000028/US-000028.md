## calendar/US-000028 — Schedule Upcoming Meetings from a Polled Calendar Source

### User Story

```
AS A User
I WANT my notifications to be scheduled automatically from the meetings that are about to start in my calendar
SO THAT I do not have to enter each meeting by hand
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Poll Interval**: default 5 min
* **Window**: default 15 min (poll interval + lead time + 5 min margin); a meeting is known to the scheduler once it starts within the window
* **Calendar Source**: an interface returning the meetings starting within a time window; only an in-memory implementation is delivered here (the Microsoft Graph one is calendar/US-000003)
* **Threading**: polling runs on a background thread, never on the JavaFX Application Thread

#### Notes
1. The poller asks the source for the meetings starting between `now` and `now + window` and schedules each of them through the scheduler of scheduler/US-000023 (trigger at start minus lead time).
2. The meeting data carried from the source is the one of calendar/US-000004: event id, title, start, end, join URL, organizer, response status, all-day flag.
3. Changes to meetings already scheduled (moved, cancelled) are scheduler/US-000030; which meetings are eligible is calendar/US-000029. In this story every returned meeting is scheduled.
4. Supersedes the scenario "Scheduler integrates with calendar polling" of scheduler/US-000011, which is not edited here.
5. The Microsoft Graph source will implement the same interface, so calendar/US-000003 should be reduced to what is specific to Graph (pagination, throttling, timezones).

### Acceptance Criteria

```gherkin
Scenario: Meeting inside the window is scheduled
  Given the poll interval is 5 minutes, the window 15 minutes and the lead time 5 minutes
  And the calendar source has "Standup" starting in 12 minutes
  When the poller runs
  Then "Standup" is scheduled to notify in 7 minutes
  And the overlay appears at that time

Scenario: Meeting beyond the window is picked up by a later poll
  Given the calendar source has "Review" starting in 40 minutes
  When the poller runs
  Then "Review" is not scheduled yet
  And a later poll, when "Review" starts within 15 minutes, schedules it

Scenario: The source is asked for the right window
  When the poller runs at 09:00
  Then the calendar source is asked for the meetings starting between 09:00 and 09:15

Scenario: Polling repeats at the poll interval in the background
  When the app has been running for 12 minutes
  Then the calendar source was polled at 0, 5 and 10 minutes
  And no poll ran on the JavaFX Application Thread

Scenario: A failing poll does not affect scheduled notifications
  Given "Standup" is already scheduled
  And the calendar source fails on the next poll
  When the poller runs
  Then the error is logged
  And the next poll runs at the normal interval
  And "Standup" still notifies on time
```
