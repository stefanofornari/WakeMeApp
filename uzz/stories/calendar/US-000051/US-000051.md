## calendar/US-000051 — Read My Calendar from an ICS Link

### User Story

```
AS A User
I WANT to give the app the ICS link of my calendar
SO THAT I get notified even where my organisation's policy blocks the Microsoft sign-in (error 530033)
```

#### Status
DONE

#### Dependencies
- calendar/US-000028
- calendar/US-000029

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Source**: an ICS implementation of the calendar-source interface of calendar/US-000028, next to the CSV and Graph ones
* **Parser**: a small reader of iCalendar written for this story (no new dependency); calendar/US-000052 decides whether recurrence needs a library
* **Option**: `--calendar` as in calendar/US-000032 and auth/US-000050

#### Notes
1. `--calendar <address>`: an `https://` address, or `webcal://` (taken as `https://`), that is not on graph.microsoft.com is an ICS feed. A path is still a CSV file, a graph.microsoft.com address is still Graph. A plain `http://` address is rejected at startup with a message saying why (the link is a secret).
2. The feed is downloaded again at every poll (timeout 30 s, redirects followed) and read as iCalendar. No sign-in, no client id.
3. Each VEVENT gives: id (`UID`), title (`SUMMARY`), start and end (`DTSTART`, `DTEND`; no end means no end), organizer (`ORGANIZER` name, else its address), description, and the join link: the first Teams or https meeting link found in `URL`, `LOCATION` or `DESCRIPTION` (the Teams link of a Outlook meeting is in the description).
4. A date without a time (`DTSTART;VALUE=DATE`) is an all-day event. `STATUS:CANCELLED` events are not returned. All-day events are returned with the all-day flag and are not notified (the eligibility filter of calendar/US-000029).
5. Eligibility, for now: everything except cancelled and all-day events. The feed does not say which attendee is the user, so what the feed says about the attendees (`PARTSTAT` of each `ATTENDEE`, never a name or an address) is logged at debug level next to the event title, so that the stricter rule (accepted, tentative, organizer only) can be switched on later. An event with no status counts as accepted.
6. Failures follow calendar/US-000028: 404 or 410 (the link was revoked or changed) is logged at SEVERE saying so, 5xx, timeouts and network errors at WARNING as temporary, a body that is not iCalendar at SEVERE; the next poll runs at the normal interval and what is scheduled keeps firing.
7. Times in a zone are converted to local time: IANA names, UTC, floating times (taken as local) and the Windows names Outlook writes, for the common zones (a table in `WindowsZones`; calendar/US-000052 completes it). An unknown zone skips that event with a warning.
8. Recurring events are calendar/US-000052; the secrecy of the link is calendar/US-000053. Until US-000052 is done, only the first occurrence of a recurring series is seen.
9. README: a section on publishing the calendar from Outlook on the web (Settings > Calendar > Shared calendars > Publish a calendar, 'Can view all details', copy the ICS link) and a troubleshooting line for error 530033 pointing to this option.

### Acceptance Criteria

```gherkin
Scenario: A meeting in the feed is notified
  Given an ICS feed with a meeting "Standup" starting in 12 minutes with a Teams link in its description
  When the app polls the feed
  Then "Standup" is scheduled and its overlay offers the Teams link

Scenario: The fields of the meeting are read
  Given an event with UID, SUMMARY, DTSTART, DTEND, ORGANIZER and DESCRIPTION
  When the source returns it
  Then id, title, start, end, organizer and description are those of the event

Scenario: Cancelled events are skipped and all-day events are flagged
  Given a cancelled event and an all-day event in the window
  When the source is asked for the meetings of the window
  Then the cancelled one is not returned
  And the all-day one is returned with the all-day flag, so it is not notified

Scenario: A changed meeting is followed
  Given a meeting was scheduled from the feed
  When the feed shows it 10 minutes later at the next poll
  Then the notification is rescheduled, as for any calendar source

Scenario: The source of --calendar is told from the address
  Given the addresses "https://outlook.office365.com/owa/calendar/x/y/calendar.ics", "webcal://host/c.ics", "https://graph.microsoft.com/v1.0/me/calendarView" and "meetings.csv"
  Then they are an ICS feed, an ICS feed, Graph and a CSV file
  And "http://host/c.ics" is rejected with a message that the link must be https

Scenario: A revoked link is reported once per poll with its reason
  Given the feed answers 404
  When the app polls
  Then an error says the link no longer works and should be published again
  And the next poll runs at the normal interval

Scenario: A temporary failure is a warning
  Given the feed answers 503 or the network is down
  When the app polls
  Then a warning says the poll will be repeated
  And already scheduled notifications still fire

Scenario: A response that is not a calendar is an error
  Given the feed answers 200 with an HTML page
  When the app polls
  Then an error says the answer is not an iCalendar feed

Scenario: The attendee status is logged when the feed has it
  Given an event with two ATTENDEE lines, PARTSTAT=DECLINED and PARTSTAT=ACCEPTED
  When the app polls with --debug
  Then the log says the feed reports "Standup" with those statuses, without names or addresses
  And the meeting is still notified (rule: everything except cancelled and all-day)

Scenario: The README explains how to get the link
  Given the README
  Then it describes publishing the calendar from Outlook on the web
  And has a line for error 530033 pointing to --calendar with the ICS link
```
