## calendar/US-000052 — Notify for Recurring Meetings and in the Right Time Zone

### User Story

```
AS A User
I WANT recurring meetings of my ICS calendar to be notified at their local time, one by one
SO THAT I am reminded of every occurrence, also when one was moved or removed, and never an hour off
```

#### Status
DONE

#### Dependencies
- calendar/US-000051

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Parser**: the reader of calendar/US-000051 is extended with `Recurrence`, written for the rules calendars use for meetings; no library
* **Poller**: unchanged; every occurrence is a separate event with its own id (calendar/US-000028)

#### Notes
1. Recurrence rules (`RRULE`: DAILY, WEEKLY, MONTHLY and YEARLY with INTERVAL, COUNT, UNTIL, BYDAY with or without an ordinal such as `2TU` or `-1FR`, BYMONTHDAY, BYMONTH, WKST) are expanded for the window asked for: only the occurrences that start in the window are returned, whatever the age of the series. `EXDATE` removes occurrences. `RECURRENCE-ID` events replace the occurrence they name (moved, renamed or cancelled for that day).
2. The id of an occurrence is the `UID` of the series plus the original start of that occurrence (`UID#2026-11-16T10:00`), so that a single occurrence moved by `RECURRENCE-ID` keeps its id and is rescheduled, not notified twice; the id of a non recurring event is its `UID`.
3. Times: UTC (`Z`), a `TZID` (IANA names, and the Windows names Outlook uses such as "W. Europe Standard Time": the table of `WindowsZones` from calendar/US-000051, completed, or the `VTIMEZONE` of the feed) and floating times are all converted to the local time of the computer. The expansion respects daylight saving time: a meeting at 10:00 in the series' zone stays at 10:00 there across the change.
4. An unknown `TZID` is not guessed: the event is skipped with a warning naming the event title and the zone, and the other events are still read.
5. A rule with anything else (BYSETPOS, BYWEEKNO, hourly frequencies, ...) is not guessed: the first occurrence is used and a warning names the meeting and what is not supported.
7. A series that is open ended is never expanded further than the window (+ the poll window of the poller), so a daily meeting for ten years costs nothing.
6. Dismissing an occurrence (notify/US-000010) hides that occurrence only, since its id is per occurrence.

### Acceptance Criteria

```gherkin
Scenario: A weekly meeting is returned for the week it falls in
  Given a weekly series every Monday at 10:00 that started a year ago
  When the source is asked for the window around next Monday 10:00
  Then it returns one occurrence starting next Monday at 10:00
  And none for the other days

Scenario: An excluded occurrence is not returned
  Given the series has an EXDATE for next Monday
  When the source is asked for that window
  Then it returns nothing

Scenario: A moved occurrence is the same meeting at its new time
  Given an override (RECURRENCE-ID) moves next Monday's occurrence to 11:30
  When the source is asked for the window around 11:30
  Then it returns the occurrence at 11:30 with the id of the original occurrence
  And none at 10:00

Scenario: A cancelled occurrence is not returned
  Given an override for next Monday with STATUS:CANCELLED
  When the source is asked for that window
  Then it returns nothing

Scenario: Time zones are converted to local time
  Given a meeting at 10:00 in "W. Europe Standard Time", one at 09:00Z and one at 10:00 floating
  And the computer is in Europe/Rome
  When the source returns them
  Then their local starts are 10:00, 10:00 (winter) or 11:00 (summer), and 10:00

Scenario: Daylight saving time does not move a recurring meeting
  Given a weekly meeting at 10:00 Europe/Rome across the last Sunday of March
  When the source returns the occurrences before and after
  Then both start at 10:00 local time

Scenario: An unknown time zone skips only that event
  Given an event with TZID "Nowhere Standard Time" and a normal event
  When the source is asked for the window
  Then a warning names the title and the zone
  And the normal event is returned

Scenario: Dismissing one occurrence leaves the next
  Given the Monday occurrence of a weekly meeting was dismissed
  When the next Monday's occurrence approaches
  Then it is notified
```
