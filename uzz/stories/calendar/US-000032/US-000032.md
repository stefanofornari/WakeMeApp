## calendar/US-000032 — Simulate the Calendar from a CSV File

### User Story

```
AS A User
I WANT to start the app on a CSV file of meetings that I can edit while it runs
SO THAT I can try the whole flow, from calendar to notification, without a real calendar
```

#### Status
DONE

#### Dependencies
- calendar/US-000028
- scheduler/US-000024

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **CLI Framework**: picocli 4.x, extending the options of notify/US-000022 and scheduler/US-000024
* **Source**: a CSV implementation of the calendar-source interface of calendar/US-000028
* **Defaults**: poll interval 5 min, window 15 min (changing them is calendar/US-000031)

#### Notes
1. Option: `--calendar <path>`. When given, `--title` and `--start-date` are no longer required, and the app polls the file instead of notifying for a single meeting. Without it nothing changes.
2. File format: UTF-8, comma separated, first line is a header naming the columns, in any order. Required columns: `id`, `title`, `start`. Optional: `end`, `url`, `organizer`, `description`, `status`, `allday`. Fields containing commas are wrapped in double quotes (`""` for a quote). Blank lines and lines starting with `#` are ignored.
3. `start` and `end` are ISO local date-times (`2026-11-07T16:30` or with seconds). `status` is one of `accepted`, `tentative`, `declined`, `none`, `organizer` (case-insensitive; empty means `accepted`). `allday` is `true` or `false` (empty means `false`).
4. The file is read again at every poll, so adding, changing or deleting a line simulates a change in the calendar. What the app does with those changes is calendar/US-000029 and scheduler/US-000030.
5. A missing file is not an error: the source returns no meetings, logs one warning naming the file (again if it disappears and reappears) and the file is picked up by the first poll after it exists. A path that is a directory is rejected at startup. A file that is unreadable or malformed fails that poll only: the error is logged with the line number and the next poll reads the file again (calendar/US-000028).
6. The process stays alive until stopped with Ctrl+C, since new meetings may appear in the file at any time.

### Acceptance Criteria

```gherkin
Scenario: Meetings in the file are read with all their fields
  Given a file with a header and a meeting "Standup" with end, url, organizer, description and status "tentative"
  When the source is asked for the meetings of the window containing it
  Then it returns "Standup" with all those fields

Scenario: Only the meetings starting in the window are returned
  Given a file with meetings starting in 5, 12 and 40 minutes
  When the source is asked for the next 15 minutes
  Then the meetings starting in 5 and 12 minutes are returned

Scenario: Quoted fields and comments are handled
  Given a title containing a comma wrapped in double quotes, a blank line and a line starting with "#"
  When the file is read
  Then the title is read intact and the blank and comment lines are ignored

Scenario: Changes to the file are seen by the next poll
  Given the source returned "Standup" starting in 12 minutes
  When the line of "Standup" is changed to start in 8 minutes
  Then the next query returns "Standup" starting in 8 minutes

Scenario: A malformed line is reported with its line number
  Given a line whose start is not a valid date-time
  When the file is read
  Then reading fails with a message naming the line number

Scenario: Starting the app on a file replaces the single meeting options
  When the user runs: app --calendar meetings.csv
  Then the command is accepted without --title and --start-date
  And the poller starts on that file

Scenario: A file that does not exist yet is waited for
  When the user runs: app --calendar missing.csv
  Then the app keeps running
  And a warning naming the file is logged once, not at every poll
  And no meeting is scheduled

Scenario: The file is picked up as soon as it becomes available
  Given the app is running and the file is missing
  When the file is created with a meeting starting in 12 minutes
  Then the next poll schedules that meeting

Scenario: A directory is rejected at startup
  When the user runs: app --calendar some-folder
  Then an error says the path is not a file
  And the command exits with a non-zero code

Scenario: A meeting in the file notifies at the usual time
  Given the app runs on a file with a meeting starting in 12 minutes
  When 7 minutes have passed
  Then the overlay appears for that meeting
  And the app keeps running after the overlay is dismissed
```
