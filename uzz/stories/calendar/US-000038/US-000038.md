## calendar/US-000038 — Skip Malformed Calendar Lines with a Warning

### User Story

```
AS A User
I WANT a malformed line in the calendar file to be skipped and reported
SO THAT one bad line does not hide all my other meetings
```

#### Dependencies

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Logging**: WARN, naming the file and the line number

#### Notes
1. Changes the behaviour decided in calendar/US-000032 (a malformed line fails the whole poll). A missing required column or an unreadable file still fails the poll (the file as a whole is the problem), reported by the poller as before.
2. The file is read at every poll, so the same bad line would be reported at every poll: each malformed line is reported once, again if its content changes or after it was fixed and broken again.
3. A skipped line is never scheduled; the other meetings of the same poll are.

### Acceptance Criteria

```gherkin
Scenario: A malformed line is skipped and reported
  Given a calendar file with a valid meeting, a line with an invalid start and another valid meeting
  When the file is read
  Then both valid meetings are returned
  And a WARN message names the file and the line number of the invalid one, and says why

Scenario: The same line is reported once
  Given the line is still malformed at the next poll
  When the file is read again
  Then no new message is logged

Scenario: A line that changes is reported again
  Given a malformed line was reported
  When the line is edited and is still malformed
  Then a new message is logged for it

Scenario: A missing required column still fails the poll
  Given a calendar file whose header has no "start" column
  When the file is read
  Then the poll fails and is reported
```
