## calendar/US-000053 — Keep the Calendar Link Secret

### User Story

```
AS A User
I WANT the link of my calendar not to appear in logs, messages or screens
SO THAT whoever sees a log or a screenshot cannot read my calendar
```

#### Status
DONE

#### Dependencies
- calendar/US-000051

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Why**: the published ICS address is the only credential; anybody who has it reads the whole calendar, no sign-in involved

#### Notes
1. Wherever the app shows the feed address it shows the host only, followed by an ellipsis: `https://outlook.office365.com/…`. This covers the start-up message, poll messages, warnings and errors, debug logs, exceptions and their causes (the message of an exception that contains the address is replaced).
2. The address is not written to any file by the app: not to the settings, nor to `dismissed.json`, nor to the log.
3. The README says what the link is, that it is not to be shared, and that the address stays in the shell history and the process list of the computer when passed on the command line; it explains how to revoke it (Outlook on the web: Publish a calendar > Unpublish).

### Acceptance Criteria

```gherkin
Scenario: Logs show the host only
  Given the app polls the feed "https://outlook.office365.com/owa/calendar/abc123/secret456/calendar.ics"
  When it starts and polls with --debug
  Then no log line contains "abc123" or "secret456"
  And the start-up message names "outlook.office365.com"

Scenario: Errors show the host only
  Given the feed answers 404, then 503, then something that is not a calendar
  When the app polls
  Then every message names the host and none contains the path of the address

Scenario: A failure of the network does not leak the address
  Given a connection error whose exception message contains the address
  When the poll fails
  Then the log and the exception chain printed contain no part of the path or query

Scenario: Nothing is saved
  Given the app ran with an ICS address
  Then the settings, dismissed.json and the log contain no part of the address

Scenario: The README explains the risk and the revocation
  Given the README
  Then it says the link must not be shared and how to unpublish the calendar
```
