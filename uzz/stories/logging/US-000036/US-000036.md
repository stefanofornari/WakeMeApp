## logging/US-000036 — Choose the Log Level with --debug

### User Story

```
AS A User
I WANT to start the application with --debug when something does not work
SO THAT the log contains the detail needed to find out why
```

#### Status
DONE

#### Dependencies
- logging/US-000034
- notify/US-000033

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **CLI Framework**: picocli 4.x; the option is added to the command of notify/US-000022

#### Notes
1. Without `--debug` the level is INFO; with it DEBUG (`FINE`), for the file and the console. No other logging option exists.
2. The level is applied to the application's loggers and to the handlers, so a DEBUG message is not dropped by a handler left at INFO.
3. It is part of the help text, so an invalid command line shows it too (notify/US-000033).

### Acceptance Criteria

```gherkin
Scenario: INFO by default
  When the application starts without --debug
  Then INFO, WARN and ERROR messages are logged
  And DEBUG messages are not

Scenario: --debug adds the detail
  When the application starts with --debug
  Then DEBUG messages are logged too, to the file and the console
  And the log says that debug logging is on

Scenario: The option is documented
  When the user runs: app --help
  Then --debug is listed with its description
```
