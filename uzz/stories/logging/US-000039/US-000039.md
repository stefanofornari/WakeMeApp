## logging/US-000039 — Log Calendar Access Failures at the Right Level

### User Story

```
AS A User
I WANT to see in the log whether a failure reading my calendar will pass by itself or needs my attention
SO THAT I do not worry about a throttled request, and I notice a refused login or a missing permission
```

#### Status
DONE

#### Dependencies
- calendar/US-000003
- calendar/US-000028
- logging/US-000037

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25; `java.util.logging`; levels as in logging/US-000037 (`WARNING` for what a user understands and should care about, `SEVERE` only for what the user MUST know)
* **Classification**: temporary (`WARNING`): HTTP 408, 429 (also after the retries are exhausted), any 5xx, network errors (timeout, DNS, connection refused). Not temporary (`SEVERE`): any other status (400, 401, 403, 404, ...), an answer that is not understood (not JSON, an event without id or start time)

#### Notes
1. `CalendarAccessException` (an `IOException`) carries `isTemporary()`; a calendar source throws it, the poller decides the level. Sources that throw a plain `IOException` (the CSV file) keep being logged at `WARNING`.
2. The message is written for the user (what failed, whether trying again will help, when the next poll is); the stack trace is kept at DEBUG only.
3. The poller keeps polling in both cases: a permanent failure may be fixed from outside (a new login, a granted permission).

### Acceptance Criteria

```gherkin
Scenario: A throttled request is a warning
  Given Microsoft Graph keeps answering 429
  When the poller reads the calendar
  Then a WARNING says that the calendar could not be read, why, and when the next poll is
  And nothing is logged at SEVERE

Scenario: A server error or a network error is a warning
  Given Microsoft Graph answers 503 or cannot be reached
  When the poller reads the calendar
  Then a WARNING says so and that it will try again at the next poll

Scenario: A refused token is severe
  Given Microsoft Graph answers 401
  When the poller reads the calendar
  Then a SEVERE message says that the calendar cannot be read, that trying again will not help, and the reason given by Graph
  And the poller keeps polling

Scenario: A missing permission is severe
  Given Microsoft Graph answers 403
  When the poller reads the calendar
  Then a SEVERE message is logged

Scenario: An answer that cannot be understood is severe
  Given Microsoft Graph answers something that is not the expected JSON
  When the poller reads the calendar
  Then a SEVERE message is logged

Scenario: Other failures of a source stay warnings
  Given a calendar source that throws an IOException that is not a calendar access failure
  When the poller reads the calendar
  Then a WARNING with the reason is logged

Scenario: Detail only with --debug
  Given a failure while reading the calendar
  When the log is at INFO
  Then the stack trace is not in the log
```
