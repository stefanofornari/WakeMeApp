## logging/US-000034 — Log to a Rolled File in the Application Data Directory

### User Story

```
AS A User
I WANT the application to write its log to a file in the application data directory
SO THAT I can look at what it did, and the file never fills my disk
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Logging**: `java.util.logging` only, configured through the JUL configuration applied once at startup (the file location is computed at startup, so the configuration is built in memory and given to `LogManager`)
* **System folders**: `dev.dirs:directories` (directories-jvm), `ProjectDirectories.dataLocalDir` + `logs`
* **Cap**: 1 MB per file, 3 files (3 MB in total at most)

#### Notes
1. File pattern `wakemeapp.%g.log` in the log folder; `FileHandler` limit 1 000 000 bytes, count 3, UTF-8, append.
2. One line per record: `2026-11-08 09:12:03 INFO  Polling meetings.csv every 5 min` (timestamp, level padded, message); an exception adds its stack trace on the following lines. Level names in the file are ERROR, WARN, INFO, DEBUG (not SEVERE/WARNING/FINE).
3. Default level INFO; changing it is logging/US-000036.
4. The qualifier, organisation and application name given to `ProjectDirectories.from` decide the folder name on each platform (on macOS they are joined in the folder name): to be settled when implementing.
5. If the folder cannot be created or written the application still starts; the failure is reported on the console and logging goes to the console only (logging/US-000035).

### Acceptance Criteria

```gherkin
Scenario: The log file is created in the application data directory
  Given the application starts for the first time
  When it logs its first message
  Then a "logs" folder exists in the application data directory of the platform
  And the file "wakemeapp.0.log" in it contains that message

Scenario: Each message is one readable line
  When the application logs "Polling meetings.csv every 5 min" at INFO
  Then the file has one line with the timestamp, the level INFO and the message

Scenario: A logged exception is followed by its stack trace
  When the application logs an error with an exception
  Then the line of the message is followed by the stack trace

Scenario: The log never grows beyond the cap
  Given the application has logged more than 3 MB of messages
  Then there are at most 3 log files
  And each is at most 1 MB
  And the oldest messages have been dropped

Scenario: An unusable log folder does not stop the application
  Given the log folder cannot be created
  When the application starts
  Then it starts anyway
  And a message on the console says that the log file cannot be used and why
```
