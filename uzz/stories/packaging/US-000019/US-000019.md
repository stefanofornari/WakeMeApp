## packaging/US-000019 — Distribution Package for Linux, macOS and Windows

### User Story

```
AS A User
I WANT to unpack one archive and start the application with a script, whatever my operating system
SO THAT I can install WakeMeApp without an installer and run it from the tray
```

#### Status
WIP

#### Dependencies
- settings/US-000054 (the application starts in the tray)

#### Technical Context & Constraints
* **macOS bundle**: on macOS, `mvn package` also builds `WakeMeApp.app` (profile `mac-app`, descriptor `src/main/assembly/mac-app.xml`, files in `src/main/dist/mac`) into `target/wakemeapp-<version>-mac-app.zip`; it has no JRE (the Java of the Mac is used) and lives in the menu bar (`LSUIElement`); `Contents/app` is the distribution
* **Target System**: Linux and macOS (`bin/wakemeapp.sh`, POSIX `sh`), Windows 10/11 (`bin\wakemeapp.bat`); Java 21 or later on the machine (not bundled)
* **Toolchain**: Maven `maven-assembly-plugin` (as in the Viber project), descriptor `src/main/assembly/bin.xml`, scripts in `src/main/dist/bin`
* **Output**: Linux `mvn package` gives `target/wakemeapp-<version>-linux-app.tar.gz` and the same tree in `target/wakemeapp-<version>-linux-app/WakeMeApp`
* **Layout**: `WakeMeApp/bin` (`wakemeapp.sh`, `wakemeapp.bat`, `wakemeapp.cmd`, `dbg`, `dbg.bat`, `dbg.cmd`, `scriptutils`), `WakeMeApp/conf/logging.properties`, `WakeMeApp/lib` (the application jar and its libraries), `WakeMeApp/lib/modules` (JavaFX), `LICENSE`
* **Started as**: `/installation/dir/WakeMeApp/bin/wakemeapp.sh` (Windows: `C:\installation\dir\WakeMeApp\bin\wakemeapp.bat`)

#### Notes
1. One story for the three systems: the scripts differ only in the shell language. The package of a platform is built on that platform, because the JavaFX jars are the ones of the building platform; there is no cross-platform archive.
2. The scripts put JavaFX on the module path and the rest on the class path, pass `--enable-native-access` and the logging configuration (the one of the sources, copied by the assembly), pass every argument to the application, and do not change the working directory (a relative path in an option stays relative to where the user is). `JAVA_HOME`, `JAVA_OPTS` and an optional `conf/wakemeapp.conf` (`conf\wakemeapp.bat`) are honoured. `dbg` runs a script with the JVM waiting for a debugger on localhost:1044.
3. The shade plugin attaches its single jar (`-shaded`), so the main artifact is the thin jar that the assembly needs.
4. **Deferred** (they were in the three stories this one replaces, and belong to other stories or to later work): installers with a bundled JRE (`jpackage`: .dmg, .msi, .deb, .rpm, .AppImage) and their signing and notarization; auto-start at login (scheduler/US-000013); a native secret store for the sign-in (Keychain, DPAPI, Secret Service: today it is an owner-only file, settings/US-000055 and auth); sleep/wake detection (scheduler/US-000027).
5. The tray works on the three systems (settings/US-000054); on Linux it needs AppIndicator support on some desktops (see the README).

### Acceptance Criteria

```gherkin
Scenario: The macOS bundle
  Given the project is packaged with Maven on a Mac
  Then target/wakemeapp-<version>-mac-app.zip contains WakeMeApp.app
  And opening it starts the application in the menu bar, with no Dock icon
  And it uses the Java 21 or later of the Mac
  And without one it says that Java is needed

Scenario: The package is built
  When the project is packaged with Maven
  Then Linux produces an archive wakemeapp-<version>-linux-app.tar.gz
  And it contains one directory WakeMeApp with bin, conf and lib
  And lib has the application jar and its libraries, and lib/modules has the JavaFX jars

Scenario: Start on Linux or macOS
  Given the archive is unpacked in /installation/dir
  When the user runs /installation/dir/WakeMeApp/bin/wakemeapp.sh
  Then the application starts in the tray

Scenario: Start on Windows
  Given the archive is unpacked in C:\installation\dir
  When the user runs C:\installation\dir\WakeMeApp\bin\wakemeapp.bat
  Then the application starts in the tray

Scenario: Options and the working directory
  Given the user is in a directory that contains meetings.csv
  When the user runs the script with --calendar meetings.csv
  Then the application reads that file
  And the options are passed on exactly as typed, also with spaces

Scenario: Started from anywhere
  Given the script is reached through a symbolic link, or the installation path has spaces
  When the user runs it
  Then the application starts

Scenario: Java
  Given JAVA_HOME points to a Java installation
  Then the script uses it
  And without JAVA_HOME it uses the java in the path

Scenario: Debugging
  When the user runs dbg wakemeapp.sh
  Then the JVM waits for a debugger on localhost:1044
```
