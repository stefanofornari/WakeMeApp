## packaging.macos/US-000019 — macOS App Packaging with Launch Agent

### User Story

```
AS A User
I WANT a native macOS installer (.dmg) that installs the app and configures it to start automatically at login
SO THAT I can install WakeMeUp like any other Mac app and it just works
```

- auth/US-000002 (Keychain token storage)

#### Technical Context & Constraints
* **Target System**: macOS 13+ (Ventura+), Apple Silicon + Intel
* **Toolchain**: `jpackage` (JDK 25), Maven `jpackage` plugin
* **Output**: `.dmg` installer with signed/notarized `.app`
* **Launch Agent**: `~/Library/LaunchAgents/com.wakemeup.plist` with `RunAtLoad=true`, `KeepAlive=true`
* **Menu Bar**: `NSStatusItem` via JNA (no Dock icon, `LSUIElement=true`)
* **Keychain**: `Security` framework via JNA for token storage
* **Sleep/Wake**: Listen for `NSWorkspaceDidWakeNotification` via JNA
* **Signing**: Developer ID Application certificate, notarization via `notarytool`
* **Runtime**: Bundled JRE (no system Java dependency)

#### Notes
1. **Architecture**: Single long-lived JVM process (not launchd periodic). The Launch Agent keeps the process alive; the JVM's internal `ScheduledExecutorService` handles polling/scheduling.
2. **Launch Agent plist** generated at install time (or first run) with correct paths to bundled Java.
3. **Menu bar only**: `Info.plist` sets `LSUIElement=1` to hide Dock icon.
4. **Entitlements**: `com.apple.security.application-groups` if needed for Keychain sharing.
5. **Auto-update**: Sparkle framework integration (future).

### Acceptance Criteria

```gherkin
Scenario: User installs .dmg and app starts at login
  Given the user downloads WakeMeUp.dmg
  And mounts it and drags WakeMeUp.app to Applications
  When the user launches WakeMeUp for the first time
  Then the app requests necessary permissions (Keychain, notifications)
  And a Launch Agent plist is created at ~/Library/LaunchAgents/com.wakemeup.plist
  And the plist has RunAtLoad=true and KeepAlive=true
  And the plist points to the bundled Java executable inside the .app

Scenario: App launches hidden at login
  Given the Launch Agent is installed
  When the user logs into macOS
  Then the app starts automatically in the background
  And no Dock icon appears
  And the menu bar icon appears in the top-right status bar
  And the scheduler begins polling (scheduler/US-000011)

Scenario: Menu bar icon uses native NSStatusItem
  Given the app is running
  When the user looks at the menu bar
  Then a template icon appears (adapts to dark/light mode)
  And clicking shows the context menu (scheduler/US-000012)
  And right-click shows the same menu

Scenario: Tokens stored in macOS Keychain
  Given the user authenticates (auth/US-000001)
  When tokens are received
  Then access token and refresh token are stored in Keychain
  And they are retrieved on subsequent launches without prompting

Scenario: Sleep/wake reschedules notifications
  Given a notification is scheduled for 9:55 AM
  And the Mac sleeps at 9:50 AM and wakes at 9:56 AM
  When the system wakes
  Then the app receives NSWorkspaceDidWakeNotification
  And the scheduler detects the missed notification
  And triggers it immediately (scheduler/US-000011)

Scenario: App is signed and notarized
  Given the .dmg is built
  When the user downloads and opens it
  Then Gatekeeper allows it without warnings
  And `spctl --assess` shows "accepted"
  And `codesign --verify` passes
```
