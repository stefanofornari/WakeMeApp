## packaging.windows/US-000020 — Windows App Packaging with Auto-Start

### User Story

```
AS A User
I WANT a native Windows installer (.msi) that installs the app and configures it to start automatically at login
SO THAT I can install WakeMeUp like any other Windows app and it just works
```

#### Dependencies
- scheduler/US-000011 (scheduler must be runnable as long-lived process)
- scheduler/US-000012 (system tray icon implementation)

#### Technical Context & Constraints
* **Target System**: Windows 10/11 (x64, ARM64)
* **Toolchain**: `jpackage` (JDK 25), WiX Toolset for .msi
* **Output**: `.msi` installer with signed `.exe`
* **Auto-Start**: Registry `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` or Startup folder shortcut
* **System Tray**: JavaFX `SystemTray` API (cross-platform)
* **Token Storage**: Windows DPAPI via JNA (`CryptProtectData`)
* **Sleep/Wake**: `WM_POWERBROADCAST` with `PBT_APMRESUMEAUTOMATIC`
* **Signing**: Code signing certificate (EV preferred for SmartScreen)
* **Runtime**: Bundled JRE (no system Java dependency)

#### Notes
1. **Architecture**: Single long-lived JVM process. Registry Run key starts the .exe at login; the JVM's internal `ScheduledExecutorService` handles polling/scheduling.
2. **System Tray**: JavaFX `SystemTray` works on Windows; fallback to JNA `Shell_NotifyIcon` if needed.
3. **DPAPI**: Tokens encrypted with user credentials, no separate password needed.
4. **Power Events**: Register for `WM_POWERBROADCAST` to detect sleep/resume.
5. **Single Instance**: Mutex to prevent multiple instances.

### Acceptance Criteria

```gherkin
Scenario: User installs .msi and app starts at login
  Given the user runs WakeMeUp.msi
  When the installation completes
  Then a Registry Run key is created at HKCU\Software\Microsoft\Windows\CurrentVersion\Run\WakeMeUp
  And the value points to the installed .exe with bundled Java

Scenario: App launches minimized to system tray at login
  Given the Run key is set
  When the user logs into Windows
  Then the app starts automatically in the background
  And no taskbar button appears (only system tray icon)
  And the system tray icon appears in the notification area
  And the scheduler begins polling (scheduler/US-000011)

Scenario: System tray icon works with JavaFX SystemTray
  Given the app is running
  When the user looks at the notification area
  Then the WakeMeUp icon appears
  And left-click shows the context menu (scheduler/US-000012)
  And right-click shows the same menu

Scenario: Tokens stored using Windows DPAPI
  Given the user authenticates (auth/US-000001)
  When tokens are received
  Then access token and refresh token are encrypted with CryptProtectData
  And they are decrypted on subsequent launches without prompting

Scenario: Sleep/wake reschedules notifications
  Given a notification is scheduled for 9:55 AM
  And the PC sleeps at 9:50 AM and wakes at 9:56 AM
  When the system wakes
  Then the app receives WM_POWERBROADCAST with PBT_APMRESUMEAUTOMATIC
  And the scheduler detects the missed notification
  And triggers it immediately (scheduler/US-000011)

Scenario: Installer is signed and passes SmartScreen
  Given the .msi is built and signed
  When the user downloads and runs it
  Then Windows SmartScreen shows publisher name (no "Unknown publisher")
  And installation completes without security warnings
```
