## packaging.linux/US-000021 — Linux App Packaging with systemd User Service

### User Story

```
AS A User
I WANT a native Linux package (.deb, .AppImage) that installs the app and configures it to start automatically at login
SO THAT I can install WakeMeUp via my package manager and it just works
```

#### Dependencies
- scheduler/US-000011 (scheduler must be runnable as long-lived process)
- scheduler/US-000012 (system tray icon implementation)

#### Technical Context & Constraints
* **Target System**: Linux (Ubuntu 22.04+, Fedora 38+, Arch, etc.), X11 + Wayland
* **Toolchain**: `jpackage` (JDK 25) for .deb/.rpm, `jpackage` + `appimage-builder` for .AppImage
* **Output**: `.deb`, `.rpm`, `.AppImage` with bundled JRE
* **Auto-Start**: systemd user service (`~/.config/systemd/user/wakemeup.service`) + `systemctl --user enable --now`
* **System Tray**: JavaFX `SystemTray` (requires `libayatana-appindicator` or `libappindicator` on Wayland)
* **Token Storage**: Secret Service (libsecret) via JNA (GNOME Keyring, KWallet)
* **Sleep/Wake**: systemd `logind` DBUS signals (`PrepareForSleep`, `PrepareForShutdown`)
* **Signing**: GPG signing for packages, AppImage with `AppImageUpdate` support
* **Runtime**: Bundled JRE (no system Java dependency)

#### Notes
1. **Architecture**: Single long-lived JVM process. systemd user service starts the app at graphical login; the JVM's internal `ScheduledExecutorService` handles polling/scheduling.
2. **System Tray**: JavaFX `SystemTray` works on X11; on Wayland needs `libayatana-appindicator3` or `libappindicator-gtk3` for Ayatana/AppIndicator support.
3. **Secret Service**: Use `org.freedesktop.secrets` DBUS API via JNA for cross-DE token storage.
4. **Sleep/Wake**: Listen to `org.freedesktop.login1.Manager.PrepareForSleep` DBUS signal.
5. **Desktop Entry**: `.desktop` file for application menu integration.

### Acceptance Criteria

```gherkin
Scenario: User installs .deb and app starts at login
  Given the user runs `sudo apt install ./wakemeup.deb`
  When the installation completes
  Then a systemd user service is installed at /usr/lib/systemd/user/wakemeup.service
  And the service has [Install] WantedBy=graphical-session.target
  And the service ExecStart points to the installed launcher with bundled Java

Scenario: App launches minimized to system tray at login
  Given the user enables the service: `systemctl --user enable --now wakemeup`
  When the user logs into their graphical session
  Then the app starts automatically in the background
  And the system tray icon appears in the panel (GNOME, KDE, etc.)
  And the scheduler begins polling (scheduler/US-000011)

Scenario: System tray works on Wayland with AppIndicator
  Given the user is on Wayland (GNOME, KDE Plasma)
  And libayatana-appindicator3 is installed
  When the app starts
  Then the system tray icon appears in the top panel
  And left/right-click shows the context menu (scheduler/US-000012)

Scenario: Tokens stored using Secret Service
  Given the user authenticates (auth/US-000001)
  When tokens are received
  Then access token and refresh token are stored via org.freedesktop.secrets
  And they are retrieved on subsequent launches without prompting
  And works with GNOME Keyring, KWallet, etc.

Scenario: Sleep/wake reschedules notifications
  Given a notification is scheduled for 9:55 AM
  And the system suspends at 9:50 AM and resumes at 9:56 AM
  When the system resumes
  Then the app receives PrepareForSleep=false DBUS signal
  And the scheduler detects the missed notification
  And triggers it immediately (scheduler/US-000011)

Scenario: .AppImage runs on any distribution
  Given the user downloads WakeMeUp.AppImage
  And runs `chmod +x WakeMeUp.AppImage && ./WakeMeUp.AppImage`
  When the AppImage runs
  Then it works without installation
  And can integrate with systemd user service via `--appimage-extract-and-run`
```
