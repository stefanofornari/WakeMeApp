## scheduler/US-000023 — Notification Scheduler Core

### User Story

```
AS A User
I WANT a meeting notification to appear automatically a few minutes before the meeting starts
SO THAT I am alerted in time without having to trigger anything myself
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Scheduler**: `ScheduledExecutorService` with a single thread
* **Lead Time**: constant 5 minutes for now; becomes configurable with settings/US-000015
* **Notification Timing**: trigger at `meetingStart.minusLeadTime`
* **Thread Safety**: the overlay is shown via `Platform.runLater()`; the scheduler never touches the UI from its own thread
* **State**: in memory only (persistence is scheduler/US-000026)

#### Notes
1. This is the first slice of the original scheduler/US-000011, which was split into scheduler/US-000023 (this story), US-000025 (background lifecycle), US-000026 (persistence) and US-000027 (sleep/wake catch-up). Calendar polling stays with calendar/US-000003 and the global on/off switch with settings/US-000017.
2. `schedule(MeetingNotification)` returns a handle that exposes the trigger time and `cancel()`. The handle is the only way to cancel for now: `MeetingNotification` has no identifier yet.
3. All time calculations use the system clock, injected as a `java.time.Clock` so tests do not have to wait.
4. A trigger time that is already in the past fires immediately instead of being dropped.

### Acceptance Criteria

```gherkin
Scenario: Notification fires at start time minus lead time
  Given a meeting starting in 10 minutes
  And the lead time is 5 minutes
  When the meeting is scheduled
  Then its trigger time is 5 minutes from now
  And nothing is shown before that time
  And the overlay is shown when that time is reached

Scenario: Multiple meetings fire independently
  Given meetings starting in 10 and 20 minutes
  And the lead time is 5 minutes
  When both are scheduled
  Then the first fires 5 minutes from now
  And the second fires 15 minutes from now
  And each fires exactly once

Scenario: Cancelled notification does not fire
  Given a scheduled meeting that has not fired yet
  When its handle is cancelled
  Then the overlay is never shown for that meeting
  And other scheduled meetings are not affected

Scenario: Trigger time already passed fires immediately
  Given a meeting starting in 2 minutes
  And the lead time is 5 minutes
  When the meeting is scheduled
  Then the overlay is shown immediately

Scenario: Overlay is shown on the JavaFX Application Thread
  Given a scheduled meeting
  When its trigger time is reached
  Then the overlay is created and shown on the JavaFX Application Thread

Scenario: Shutting down the scheduler drops pending notifications
  Given two scheduled meetings that have not fired yet
  When the scheduler is shut down
  Then neither meeting fires
```
