## scheduler/US-000027 — Catch Up on Missed Notifications After Sleep or Wake

### User Story

```
AS A User
I WANT notifications that came due while my computer was asleep to appear when it wakes up
SO THAT closing the laptop lid does not make me miss a meeting
```

#### Dependencies
- scheduler/US-000023

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Detection**: a watchdog tick detects wake-up from a jump of the system clock, so it works on every platform

#### Notes
1. Split out of scheduler/US-000011. `ScheduledExecutorService` delays are measured in monotonic time, which can stand still during sleep, so after a wake-up the pending schedule is recomputed from the wall clock.
2. Native wake events (`NSWorkspaceDidWakeNotification` on macOS, `WM_POWERBROADCAST` on Windows, logind `PrepareForSleep` on Linux) can be added later as faster triggers for the same catch-up logic.
3. Meetings that have already ended when the app wakes up are skipped, not shown.

### Acceptance Criteria

```gherkin
Scenario: Missed notification is shown after wake
  Given a notification is scheduled for 09:55
  And the system sleeps at 09:50 and wakes at 09:56
  When the wake-up is detected
  Then the overlay is shown within 10 seconds
  And the overlay shows the correct time to the meeting start

Scenario: Notifications that are not yet due stay scheduled
  Given notifications are scheduled for 09:55 and 10:25
  And the system sleeps at 09:50 and wakes at 09:56
  When the wake-up is detected
  Then the 10:25 notification is still scheduled for 10:25

Scenario: Meeting that ended during sleep is skipped
  Given a notification for a meeting ending at 10:30
  And the system wakes at 10:45
  When the wake-up is detected
  Then no overlay is shown for that meeting

Scenario: Normal operation is not mistaken for a wake-up
  Given the system is running normally
  When the watchdog ticks on schedule
  Then no catch-up is performed
```
