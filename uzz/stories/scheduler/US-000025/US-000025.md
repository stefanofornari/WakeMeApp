## scheduler/US-000025 — Background Process Lifecycle

### User Story

```
AS A User
I WANT the app to keep running without any visible window
SO THAT scheduled notifications can still appear when their time comes
```

#### Dependencies

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Process Model**: single long-lived JVM, started by the platform launcher (packaging stories) and kept alive by it

#### Notes
1. Split out of scheduler/US-000011. The JavaFX runtime must not exit when the last window closes: `Platform.setImplicitExit(false)`.
2. The tray / menu bar icon and its Quit entry belong to scheduler/US-000012; this story only provides the application-level shutdown they will call.
3. Shutdown cancels pending notifications and hides any visible overlay before the JVM ends.

### Acceptance Criteria

```gherkin
Scenario: App stays alive with no window
  Given the app is started
  And a notification is scheduled
  When no window is visible
  Then the process keeps running

Scenario: App stays alive after an overlay is dismissed
  Given an overlay is visible and another notification is scheduled
  When the user dismisses the overlay
  Then the process keeps running
  And the other notification still fires on time

Scenario: Shutdown cleans up
  Given a visible overlay and a pending notification
  When the application is asked to shut down
  Then the overlay is closed
  And the pending notification is cancelled
  And the process ends with exit code 0
```
