## scheduler/US-000030 — Keep Scheduled Notifications in Sync with Calendar Changes

### User Story

```
AS A User
I WANT my pending notifications to follow my calendar when meetings are moved or cancelled
SO THAT I am notified at the right time and never for a meeting that no longer happens
```

#### Status
DONE

#### Dependencies
- calendar/US-000028
- scheduler/US-000023
- notify/US-000009

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Identity**: a meeting is identified by its calendar event id; a changed start time reschedules the same notification instead of creating a new one

#### Notes
1. Each poll reconciles the meetings returned by the source with the scheduled notifications: unknown meeting → schedule; changed start time → reschedule; missing or no longer eligible → cancel; unchanged → leave alone.
2. A rescheduled meeting has its snooze count reset to zero, and a pending snooze for it is replaced by the notification for the new start time.
3. Pending snoozes of unchanged meetings are not touched by a poll.
4. A meeting already shown and dismissed does not notify again unless its start time changes.
5. Needs the scheduler to cancel and replace a scheduled notification by meeting id (the handle of scheduler/US-000023 already supports cancel).

### Acceptance Criteria

```gherkin
Scenario: A moved meeting notifies at its new time only
  Given "Standup" is scheduled to notify at 09:55 for a 10:00 start
  When a poll reports "Standup" now starting at 10:20
  Then the notification is rescheduled to 10:15
  And nothing happens at 09:55

Scenario: A cancelled meeting never notifies
  Given "Standup" is scheduled
  When a poll no longer returns "Standup"
  Then its notification is cancelled and never fires

Scenario: A meeting that becomes ineligible is cancelled
  Given "Standup" is scheduled
  When a poll reports that the user declined it
  Then its notification is cancelled

Scenario: An unchanged meeting is not duplicated
  Given "Standup" is scheduled
  When the next poll returns "Standup" unchanged
  Then it is still scheduled exactly once
  And it notifies exactly once

Scenario: A pending snooze survives a poll
  Given the user snoozed "Standup" for 5 minutes
  When a poll returns "Standup" unchanged before the snooze ends
  Then the snooze still notifies when it ends

Scenario: Rescheduling resets the snooze count
  Given "Standup" has been snoozed 2 times
  When a poll reports a new start time for "Standup"
  Then its notification is rescheduled for the new start time
  And the snooze count is 0 when it appears
```
