## scheduler/US-000024 — Schedule a Notification from the Command Line

### User Story

```
AS A User
I WANT to schedule a meeting notification from the command line, or show it immediately
SO THAT I can test the real timing of notifications and drive them from external scripts
```

#### Status
WIP

#### Dependencies
- notify/US-000022
- scheduler/US-000023

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **CLI Framework**: picocli 4.x, extending the options of notify/US-000022
* **Process Model**: the command line invocation schedules the notification in its own JVM and stays alive until it has fired and the overlay is dismissed. Handing the meeting over to an already running background instance is out of scope for this story.

#### Notes
1. `--start-date` keeps its meaning and is still required: it is the meeting start shown on the overlay and the reference for the trigger time.
2. Without `--now` the notification is scheduled through the scheduler of scheduler/US-000023: it fires at `start-date` minus the lead time (5 minutes until settings/US-000015). If that moment has already passed it is shown immediately.
3. New flag `-n`/`--now`: show the notification immediately, regardless of `--start-date`. This is the behaviour notify/US-000022 had before this story; its scenarios now apply when `--now` is given.
4. On start the command prints when the notification will fire, for example `Scheduled "Team Standup" for 09:55 (in 4 min)`, so that a scheduled run is not mistaken for a hang.
5. Exit codes and error handling stay as in notify/US-000022: non-zero on validation errors, 0 once the overlay has been dismissed.

### Acceptance Criteria

```gherkin
Scenario: Notification is scheduled for start time minus lead time
  Given the lead time is 5 minutes
  When the user runs: app --title "Team Standup" --start-date "<now + 10 minutes>"
  Then no overlay is shown yet
  And the command prints that the notification will fire in 5 minutes
  And the overlay appears 5 minutes after the command was started
  And the command exits with code 0 once the overlay is dismissed

Scenario: --now shows the notification immediately
  Given the lead time is 5 minutes
  When the user runs: app --title "Team Standup" --start-date "<now + 10 minutes>" --now
  Then the overlay appears immediately with title "Team Standup"
  And the command exits with code 0 once the overlay is dismissed

Scenario: Start date within the lead time is shown immediately
  Given the lead time is 5 minutes
  When the user runs: app --title "Team Standup" --start-date "<now + 2 minutes>"
  Then the overlay appears immediately

Scenario: Optional arguments are shown when scheduled
  Given the user runs the command with --end-date, --organizer and --url
  When the notification fires
  Then the overlay shows the end time and the organizer
  And the Join button opens the given URL

Scenario: Invalid arguments are rejected before anything is scheduled
  When the user runs: app --title "Team Standup" --start-date "invalid-date"
  Then the command prints an error about the date format
  And nothing is scheduled
  And the command exits with a non-zero code

Scenario: Interrupting the command cancels the scheduled notification
  Given a notification scheduled for later
  When the user stops the command with Ctrl+C
  Then the notification never fires
```
