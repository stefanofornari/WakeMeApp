## scheduler/US-000026 — Persist Pending Notifications Across Restart

### User Story

```
AS A User
I WANT scheduled notifications to survive an app restart
SO THAT quitting or crashing the app does not make me miss a meeting
```

#### Status
TODO

#### Dependencies
- scheduler/US-000023

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Storage**: a local JSON file in the user's application data folder (Jackson is already a dependency)

#### Notes
1. Split out of scheduler/US-000011. Each entry stores the meeting data and its trigger time, which is all that is needed to rebuild the schedule.
2. The file is rewritten on every schedule, cancel and fire, so it always mirrors the in-memory state.
3. A notification whose trigger time passed while the app was not running is handled by scheduler/US-000027, not here.

### Acceptance Criteria

```gherkin
Scenario: Pending notifications are restored after restart
  Given notifications are scheduled for 09:55 and 10:25
  And the app is quit at 09:50
  When the app is started again at 09:52
  Then both notifications are scheduled again
  And the 09:55 one fires on time

Scenario: Fired notifications are not restored
  Given a notification has fired and been dismissed
  When the app is restarted
  Then that notification is not scheduled again

Scenario: Cancelled notifications are not restored
  Given a notification was cancelled
  When the app is restarted
  Then that notification is not scheduled again

Scenario: Unreadable store does not prevent startup
  Given the persisted file is corrupted
  When the app is started
  Then it starts with an empty schedule
  And a warning is logged
```
