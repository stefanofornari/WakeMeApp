## auth/US-000040 — Handle Device Code Sign-In Failures

### User Story

```
AS A User
I WANT a clear message and a way to try again when the sign-in does not complete
SO THAT a declined, expired or failed sign-in does not leave the application stuck
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25; HTTP with the JDK `HttpClient`, JSON with org.json; tested against stubbed HTTP (xtest, see `uzz/library/HOWTO StubHttpClient.md`), never against the real service
* **Errors of the token endpoint** (RFC 8628): `authorization_pending`, `slow_down`, `authorization_declined`, `expired_token`, `bad_verification_code`; the device code answer can fail too (for instance an unknown client id)

#### Notes
1. `slow_down` is not a failure: the polling interval grows by 5 seconds for the rest of the flow.
2. The messages are for the user and say what to do ("the code expired, start the sign-in again"); the reason given by Microsoft (`error_description`) is included.
3. A failure that will not pass by itself (declined, unknown client, bad request) is logged at SEVERE, a failure that may pass (network, server error while polling) at WARNING, as in logging/US-000039.
4. Trying again means calling the sign-in again: it asks for a new device code.

### Acceptance Criteria

```gherkin
Scenario: Microsoft asks to slow down
  Given the polling interval is 5 seconds
  When the token endpoint answers slow_down
  Then the next request is sent after 10 seconds
  And the later ones keep the longer interval

Scenario: The user declines
  Given a sign-in is waiting for the user
  When the token endpoint answers authorization_declined
  Then the polling stops
  And a SEVERE message tells that the sign-in was declined
  And the sign-in can be started again

Scenario: The code expires
  Given the user does not enter the code before expires_in seconds
  When the code has expired (expired_token, or the time has passed)
  Then the polling stops
  And a message tells that the code expired and that the sign-in must be started again
  And starting it again requests a new device code

Scenario: A network error while waiting does not end the sign-in
  Given a sign-in is waiting for the user
  When a request to the token endpoint fails because of the network
  Then a WARNING is logged
  And the polling goes on at the next interval until the code expires

Scenario: The device code cannot be requested
  Given the client id is not known to Microsoft
  When the sign-in starts
  Then a SEVERE message gives the reason from Microsoft
  And no polling is started
```
