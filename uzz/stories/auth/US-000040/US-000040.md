## auth/US-000040 — Handle Device Code Sign-In Failures

### User Story

```
AS A User
I WANT a clear message and a way to try again when the sign-in does not complete
SO THAT a declined, expired or failed sign-in does not leave the application stuck
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25; MSAL4J (`com.microsoft.azure:msal4j`); tested with MSAL's HTTP client replaced by a stub (see auth/US-000001/notes.md), never against the real service
* **Failures**: MSAL reports them as exceptions of the sign-in future (service errors with an error code and description, client errors, network errors); the user declining, the code expiring, an unknown client id and a tenant that does not exist are the cases to cover

#### Notes
1. The polling (`authorization_pending`, `slow_down`) is MSAL's and is not tested here.
2. The messages are for the user and say what to do ("the code expired, start the sign-in again"); the reason given by Microsoft is included.
3. A failure that will not pass by itself (declined, unknown client, unknown tenant) is logged at SEVERE, a failure that may pass (network) at WARNING, as in logging/US-000039.
4. Trying again means calling the sign-in again: it asks for a new device code.
5. Which MSAL exceptions and error codes map to which message is confirmed against the stub when implementing.

### Acceptance Criteria

```gherkin
Scenario: The user declines
  Given a sign-in is waiting for the user
  When the token endpoint answers authorization_declined
  Then the sign-in ends
  And a SEVERE message tells that the sign-in was declined
  And the sign-in can be started again

Scenario: The code expires
  Given the user does not enter the code in time
  When the token endpoint answers expired_token
  Then the sign-in ends
  And a message tells that the code expired and that the sign-in must be started again
  And starting it again requests a new device code

Scenario: The device code cannot be requested
  Given the client id is not known to Microsoft
  When the sign-in starts
  Then a SEVERE message gives the reason from Microsoft
  And the sign-in ends

Scenario: The network fails
  Given no connection to Microsoft
  When the sign-in starts
  Then a WARNING says that Microsoft cannot be reached
  And the sign-in can be started again
```
