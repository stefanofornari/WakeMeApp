## auth/US-000001 — Device Code Flow Authentication

### User Story

```
AS A User
I WANT to authenticate with Microsoft Graph using Device Code Flow
SO THAT I can securely access my Outlook/Teams calendar without entering credentials in the app
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25
* **Auth Flow**: OAuth 2.0 Device Authorization Grant (RFC 8628)
* **Endpoint**: `https://login.microsoftonline.com/{tenant}/oauth2/v2.0/devicecode`
* **Scopes**: `Calendars.Read`, `User.Read`

#### Notes
1. On first launch, app displays a user code and opens browser to `https://microsoft.com/devicelogin`
2. Poll token endpoint until user completes authentication or timeout (15 min default)
3. Store refresh token securely for subsequent launches
4. Handle tenant-specific endpoints (common, organizations, or specific tenant ID)

### Acceptance Criteria

```gherkin
Scenario: First-time authentication succeeds
  Given the app is launched for the first time
  And no valid tokens exist in storage
  When the authentication flow is initiated
  Then a device code and user code are displayed
  And the default browser opens to https://microsoft.com/devicelogin
  And the user enters the code and consents to permissions
  Then an access token and refresh token are received
  And tokens are stored securely in local encrypted file

Scenario: Authentication times out
  Given the device code flow is initiated
  And the user does not complete authentication within 15 minutes
  When the polling exceeds the token endpoint's expiration
  Then an error is displayed to the user
  And the authentication flow can be retried

Scenario: Subsequent launch uses stored refresh token
  Given a valid refresh token exists in secure storage
  When the app launches
  Then the refresh token is used to obtain a new access token silently
  And no browser interaction is required
  And the app proceeds to calendar polling
```
