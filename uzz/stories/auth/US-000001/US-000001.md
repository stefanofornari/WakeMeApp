## auth/US-000001 — Sign In with the Device Code Flow

### User Story

```
AS A User
I WANT to sign in to Microsoft with a code I type in the browser
SO THAT WakeMeApp can read my Outlook calendar without ever seeing my password
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25; HTTP with the JDK `HttpClient`, JSON with org.json; tested against stubbed HTTP (xtest, see `uzz/library/HOWTO StubHttpClient.md`), never against the real service
* **Auth Flow**: OAuth 2.0 Device Authorization Grant (RFC 8628), public client (no secret)
* **Endpoints**: `https://login.microsoftonline.com/{tenant}/oauth2/v2.0/devicecode` and `.../token`; `{tenant}` is `common`, `organizations`, `consumers` or a tenant id
* **Scopes**: `Calendars.Read User.Read offline_access` (`offline_access` is what yields the refresh token)

#### Notes
1. Replaces the first draft of this story: the failure paths (US-000040), the silent refresh (US-000041), the re-authentication (US-000042) and persistence (US-000002) are separate stories.
2. Tenant id and client id are parameters of the sign-in; the settings story (settings/US-000014) provides them later, a command line option is enough meanwhile.
3. The result is an access token supplier (`Supplier<String>`), the one `GraphCalendarSource` (calendar/US-000003) already takes. Tokens are only kept in memory here.
4. The user code and the address are shown in the log at INFO, worded for the user ("Open https://microsoft.com/devicelogin and enter the code ABCD-EFGH"); a dialog belongs to the UI stories. The browser is opened through an injectable URL opener (also needed by notify/US-000007); if it cannot be opened the message is still shown.
5. The token endpoint is polled at the `interval` of the answer (5 s if missing) until the answer is a token.

### Acceptance Criteria

```gherkin
Scenario: A device code is requested and shown
  Given a tenant id and a client id
  When the sign-in starts
  Then a request with the client id and the scopes is sent to the device code endpoint of the tenant
  And the user code and the verification address are shown to the user
  And the browser is opened on the verification address

Scenario: The token endpoint is polled until the user is done
  Given a device code was issued with a polling interval of 5 seconds
  And the user has not yet entered the code
  When the token endpoint answers authorization_pending
  Then it is asked again after the interval
  And the polling continues until it answers with the tokens

Scenario: The tokens are available after the sign-in
  Given the user entered the code and consented
  When the token endpoint answers with an access token, a refresh token and expires_in
  Then the access token supplier returns that access token
  And the expiry time of the access token is known

Scenario: The tenant selects the endpoint
  Given the tenant "organizations"
  When the sign-in starts
  Then the requests go to the endpoints of the tenant "organizations"

Scenario: The browser cannot be opened
  Given no browser can be opened
  When the sign-in starts
  Then the user code and the address are still shown
  And the polling goes on
```
