## auth/US-000049 — Show the Microsoft Sign-In Page in a WebView

### User Story

```
AS A User
I WANT the Microsoft sign-in page to open inside WakeMeApp with the code shown next to it
SO THAT I can sign in without switching to another program
```

#### Status
DONE

#### Dependencies
- auth/US-000001 (provides the `VerificationPresenter` this story implements)

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app; `javafx.web` (WebView)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25

#### Notes
1. A small window with the message and the user code (selectable and copyable) above a `WebView` loaded on the verification address.
2. The window closes when the sign-in completes; closing it by hand does not cancel the sign-in (it goes on until the code expires, auth/US-000040).
3. If the page does not work in a WebView (blocked by the tenant, or rendering problems) the window offers "Open in the browser" with the same address.
4. The first step is a spike against a real account to check that the sign-in page works in a JavaFX WebView; the result is written in `notes.md`. If it does not, the story becomes "open the system browser" and the WebView is dropped.
5. The WebView keeps no sign-in cookies between runs (the tokens are in the token store, auth/US-000002).

### Acceptance Criteria

```gherkin
Scenario: The page and the code are shown
  Given a verification address and a user code
  When the presenter is asked to show them
  Then a window shows the user code
  And its WebView loads the verification address

Scenario: The window closes when the sign-in completes
  Given the window is open
  When the sign-in completes
  Then the window closes

Scenario: Fall back to the browser
  Given the window is open
  When the user chooses "Open in the browser"
  Then the verification address is opened in the system browser

Scenario: Closing the window does not cancel the sign-in
  Given the window is open
  When the user closes it
  Then the sign-in is still waiting for the user
```
