## auth/US-000043 — Encrypt the Stored Sign-In with the macOS Keychain

### User Story

```
AS A User
I WANT my saved sign-in to be unreadable by other programs
SO THAT someone who copies the token file cannot use my Microsoft account
```

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25; HTTP with the JDK `HttpClient`, JSON with org.json; tested against stubbed HTTP (xtest, see `uzz/library/HOWTO StubHttpClient.md`), never against the real service
* **Encryption**: AES-256-GCM, a random key generated at first use
* **Key storage**: the macOS Keychain, never next to the file
* **Platform**: macOS only; the equivalents for Windows (DPAPI) and Linux (Secret Service) and a password fallback belong to the future platforms of the scope and have no story yet

#### Notes
1. An encrypted `TokenStore` replaces the file store of auth/US-000002; the sign-in code does not change.
2. How the key reaches the Keychain (the `security` command or a native call) is decided when implementing; the key must never appear in the arguments of a process, where other users can read it.
3. A file that cannot be decrypted (key missing from the Keychain, file damaged or modified: the GCM tag fails) is treated as empty, with a WARNING; the user signs in again.

### Acceptance Criteria

```gherkin
Scenario: The token file is encrypted
  Given the user has signed in
  When the refresh token is stored
  Then the token file does not contain the refresh token in the clear
  And the key is kept in the macOS Keychain, not in the file or next to it

Scenario: The key is created at first use
  Given there is no key in the Keychain
  When the first token is stored
  Then a new random 256-bit key is created and kept in the Keychain

Scenario: The stored sign-in is read back
  Given an encrypted token file and its key in the Keychain
  When the application starts
  Then the refresh token is decrypted and used

Scenario: The key is gone
  Given an encrypted token file and no key in the Keychain
  When the application starts
  Then a WARNING says that the saved sign-in cannot be read
  And the device code sign-in is started

Scenario: The file was modified
  Given the encrypted token file was changed
  When the application starts
  Then it is not accepted, a WARNING is logged and the device code sign-in is started
```
