## auth/US-000050 — Read My Outlook Calendar from a Graph Address

### User Story

```
AS A User
I WANT to give the address of my Outlook calendar and get reminders for its meetings
SO THAT I am warned about my real meetings, not about a file I keep by hand
```

#### Status
WIP

#### Dependencies
- auth/US-000001
- calendar/US-000003

#### Technical Context & Constraints
* **Target System**: JavaFX desktop app (macOS primary)
* **Toolchain / Rules**: Maven + JavaFX 25 + Java 25; MSAL4J (`com.microsoft.azure:msal4j`); tested with MSAL's HTTP client replaced by a stub (see auth/US-000001/notes.md), never against the real service
* **Option**: `--calendar` (picocli, `NotificationCommand`)

#### Notes
1. `--calendar` takes a CSV file (a path, as today) or the full address of an Outlook calendar on Microsoft Graph, e.g. `https://graph.microsoft.com/v1.0/me/calendarView` (default calendar) or `https://graph.microsoft.com/v1.0/me/calendars/{calendar-id}/calendarView`. An address makes the application sign in (auth/US-000001) and poll that calendar with `GraphCalendarSource` and the access token supplier; a file makes it read the file and skip the sign-in. The query (`startDateTime`, `endDateTime`, `$select`, `$orderby`, `$top`) is ours; `/calendarView` is added if the address does not end with it.
2. The access token is only sent to `graph.microsoft.com` over https: any other address is refused at start with a message naming the option, so a wrong address never receives the token. The address of the calendar in the Outlook web app is not an endpoint and is refused the same way.
3. An address needs a client id (stored or `--client-id`, settings/US-000046); without one the application stops at start with a message saying so.
4. While there is no valid sign-in (before the first one completes, or while a new one is waiting after auth/US-000042) the polling does not read the calendar; it logs a WARNING "waiting for the sign-in" at each poll, as in logging/US-000039, and starts reading as soon as the sign-in completes.
5. Shared calendars of other users (extra scope `Calendars.Read.Shared`) and a short form such as `graph:me` are future items (main scope).

### Acceptance Criteria

```gherkin
Scenario: The calendar is read from Outlook after the sign-in
  Given --calendar is "https://graph.microsoft.com/v1.0/me/calendarView" and the user has signed in
  When the calendar is polled
  Then that calendar is requested with the access token
  And its meetings are scheduled as notifications

Scenario: No polling until the sign-in is done
  Given the sign-in is waiting for the user
  When the poll time comes
  Then the calendar is not read
  And a WARNING says that the application is waiting for the sign-in

Scenario: A file keeps working without a sign-in
  Given --calendar is a CSV file
  When the application starts
  Then the file is read
  And no sign-in is started

Scenario: An address on another host is refused
  Given --calendar is "https://example.com/v1.0/me/calendarView"
  When the application starts
  Then it stops with a message that the calendar address must be on graph.microsoft.com
  And no token is requested or sent

Scenario: An address without a client id
  Given --calendar is a Graph address and no client id is stored or given
  When the application starts
  Then it stops with a message saying that a client id is needed
```
